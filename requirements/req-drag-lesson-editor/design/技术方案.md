## 2. 架构概览

### 2.1 分层

编辑器是一个**跨 sim 的作者侧工具**（非单一 sim），因此新建独立模块目录，不混入 `lib/<sim>/`。

├── screens/
│   └── lesson_editor_screen.dart       ← 九宫格主屏（F2~F14 组装）

├── canvas/
│   ├── lesson_canvas_view.dart         ← 节点连线画布（center 格 · 新建 · T1）
│   ├── lesson_node_card.dart           ← 节点卡片（可拖/可选/角标）

### 2.2 模块归属依据（新 `lib/lesson_editor/` 而非 `lib/<sim>/`）

- **语义**：编辑器是跨 sim 的**作者侧工具**，不属于任何单一 sim（不经 `LessonSimHosts.dispatch` 分发进宿主）；`lib/<sim>/` 全是"运行时 sim 宿主"，混入作者工具会污染 sim 边界。
- **先例**：`lib/screens/home_screen.dart` / `lib/screens/scenario_selection_screen.dart` 是跨模块导航/选择屏，保留在顶层 `screens/`（shared-abstraction-plan 债务 P1 §五 顶层遗留合法结论）。但编辑器体量大（>10 文件），不宜放顶层 `screens/` 散落，故独立成 `lib/lesson_editor/` 一级目录。
- **依赖方向**：`lesson_editor/` 只依赖 `lib/common/`（DragDropWorkspace/DropCanvas/DragTray/PropertyControlPanel/NineGridLayout/lesson 数据模型）+ 只读运行时 `LessonSimHosts`（场景清单数据源）。**反向依赖不成立**——不要求 `lib/<sim>/` 依赖编辑器。

## 3. 关键决策（T1~T5）

### 3.1 T1 · 节点连线画布（最大技术风险）——**扩展 DropCanvas 之上的新画布层**

**结论**：**在 `DropCanvas` 之上新增 `LessonCanvasView` 连线交互层，不复用物理元件拖放语义。** 复用 `DropCanvas` 的**画布投影 + 拖入落点**机制承载"拖入新节点"（F2/AC-2），但节点**连线交互**（拖手柄→目标）是全新能力，需新组件。

**依据**：
- 已核实 `DropCanvas`（`drag_drop_workspace.dart:114-150`）是 `DragTarget<T>`，只负责"托盘元件 → 画布落点"单向拖放，`onItemDropped(T, worldPos)` 回调后即交还 Screen——**无节点间连线、无拖出手柄、无连线渲染**。物理元件语义（电路 wire / 光学光线）不适用剧本"节点→节点"流转。
- 项目 UI 范式（`ui-framework.md` §一）：`Stack`（CustomPaint 底层连线 + Positioned 节点 Widget 中层）+ `GestureDetector` 交互，`SceneProjection` 统一坐标。连线层应作为**新增 CustomPainter**（`LessonEdgePainter`）遵循该范式。

**实现方案**：
- 复用：`DropCanvas`（`projectionFactory: (sz) => SceneProjection(origin: Offset.zero)` 以 1:1 屏幕坐标承载节点布局）+ `DragTray`/`DragItem`/`DragItemCard`（节点库）+ `SceneProjection`。
- 新增 `LessonCanvasView`（StatelessWidget，无内部状态）：
  - 输入：`List<LessonNodeUi>`（节点含 id/title/类型/屏幕坐标）+ `List<LessonEdge>`（连线）+ 回调 `onNodeMoved` / `onNodeSelected` / `onEdgeDragStart/onEdgeDragEnd` / `onNodeDrop`。
  - 内部：`Stack` = 底层 `CustomPaint(LessonEdgePainter)`（画连线）+ 中层 `Positioned(LessonNodeCard)`（节点，可拖/可选）+ 顶层连线手柄拖拽热区。
  - 连线交互：每节点卡片右下角渲染"连线手柄"（小圆点），`GestureDetector.onPanUpdate` 拖拽生成临时边（从源节点手柄 → 当前指针），松开时 `onEdgeDragEnd(指针位置)` 由 Screen 做目标节点命中判定（`pointInRect`，复用 `hit_test` 几何纯函数思路）。
  - 拖动手柄用 `IgnorePointer` 排除对底层 `DropCanvas` 拖放的干扰（参考 `drag_drop_workspace.md` §设计要点）。
- `LessonEdgePainter`（CustomPainter，遵循 `ui-framework.md` §四 规范：构造注入不可变数据 + `SceneProjection` 转坐标 + `shouldRepaint` 引用比较）：
  - `next` → 实线箭头（直线/正交贝塞尔）
  - `onCompleted` → 实线箭头 + 端点"完成后"标签
  - `routes` → 分叉主干 + N 支线，各标条件名，末项兜底虚线
  - 冲突边 → 黄色虚线 + 警告图标（F14）

**影响面**：新增 `lesson_editor/canvas/` 两文件（`LessonCanvasView` + `LessonEdgePainter`）；登记 L1 候选第 1/3 用户。不触碰 `drag_drop_workspace.dart` 本体（零回归）。

### 3.2 T2 · 场景选择器动态刷新（已拍板）——**注册表驱动 + 双刷新机制**

**结论**：**注册表驱动，非硬编码 enum**。编辑器从 `LessonSimHosts` 已注册 sim + 各 sim `ScenarioManager.scenarios` 动态读候选清单；提供"进入时加载 + 手动刷新按钮"双刷新机制。

**依据**（`notes.md` 决策记录 + 交互指南 §4.1.1 + §9 T2 方案 A）：
- `LessonSimHosts`（`lesson_sim_host.dart:22-27`）当前 `_circuitMgr`/`_cvMgr` 是**私有静态字段**，编辑器无法直接读 `scenarios`。
- `ScenarioManagerBase.scenarios`（`scenario_manager_base.dart:77`）已暴露只读 `List<TScenario>`，`loadScenarios()` 幂等可重入（`_scenarios.clear()` + 重读，`scenario_manager_base.dart:80-102`）。
- 用户 2026-08-26 拍板：新增 sim 后编辑时**必须刷新出来**（无需重启）。

**实现方案**：
1. **数据源访问器**：在 `lesson_sim_host.dart` 增加**只读公开访问器**（不改 `dispatch`/`scenarioPlayable` 语义）：
   ```dart
   // 供 lesson_editor 读取场景清单（T2）
   static Future<Map<String, List<String>>> loadSceneCatalog() async {
     await ensureManagersLoaded();
     return {
       'circuit': [_circuitMgr?.scenarios.map((s) => s.scenarioId).toList() ?? []],
       'color_vision': [_cvMgr?.scenarios.map((s) => s.scenarioId).toList() ?? []],
     };
   }
   ```
   > 注：仅列出**已注册且 `scenarioPlayable` 为 true** 的 sim + 场景（与运行时消费一致）。需在访问器内复用 `scenarioPlayable` 闭包过滤不可玩场景。
2. **刷新机制**（交互指南 §4.1.1 落地）：
   - **进入编辑器时**：`LessonEditorScreen.initState` 调 `LessonSimHosts.ensureManagersLoaded()`（幂等）+ 调 `loadSceneCatalog()` 重建场景选择器数据（跨会话必新）。
   - **手动刷新**：`SceneSelector` 旁 `Icons.refresh_rounded` 按钮 → 重新 `loadSceneCatalog()` 并 `setState`（编辑会话中新增 sim 后点一下即出新 sim + 场景）。
3. **新增 sim 接线 4 处**（运行时侧 · 编辑侧零改动 · 接线后自动出现）：见 §4 专项。

**影响面**：`lesson_sim_host.dart` 加一个只读访问器方法（不改现有 3 处接线语义）+ 编辑器 `SceneSelector`。schema enum 仍是封闭集但**仅用于运行时校验，不阻塞编辑器选新 sim**——若新增 sim 未接线 schema enum，编辑时可选但保存前 `LessonValidator` 会提示 schema 校验失败（引导接线），符合"接线后自动可用"。

### 3.3 T3 · 节点布局持久化——**外置 `.layout.json`**

**结论**：**外置 `assets/lessons/<lessonId>.layout.json`**，运行时忽略。不扩展 `lesson.schema.json`（保持纯运行时数据契约，C1/C4）。

**依据**：
- `lesson.schema.json` 无任何 UI 布局字段（已核实 schema 全文，`additionalProperties:false` 也不允许加 metadata）。
- 扩展 schema 会破坏运行时兼容（C3 向后兼容 + schema 封闭 `additionalProperties:false`）。
- 纯自动布局每次导入无法还原用户手动摆位（交互指南 §3.2 用户会拖动节点调整位置）。

**实现方案**：
- `.layout.json` 结构（**editor-only，运行时零读取**）：
  ```json
  {
    "lessonId": "cross-sim-explore",
    "nodes": {
      "n1": { "x": 120, "y": 80 },
      "n2": { "x": 360, "y": 80 }
    }
  }
  ```
- 保存时：`<lessonId>.json`（schema 契约）与 `<lessonId>.layout.json`（布局）**成对写入**。
- 导入时：读 `<lessonId>.layout.json`；缺失/损坏 → 降级走 `LessonAutoLayout`（层流自动布局：entry 起 BFS，按 level 横向排布）。
- 删除/新增节点 → 同步维护 `.layout.json` 的 nodes map。
- **不碰 `assets/lessons/manifest.json`**（manifest 只列运行时 lesson 条目，不含布局）。

**影响面**：`lesson_editor/validation/lesson_importer.dart` + `lesson_editor/` 新增 `LessonAutoLayout`（L1 候选）。运行时侧零改动。

### 3.4 T4 · 高级 JSON 模式——**MVP 用 TextField + 格式化按钮**

**结论**：**MVP 用纯 `TextField`（多行等宽字体）+「格式化」「校验」「应用」按钮**；语法高亮/实时校验后置（非本期）。

**依据**：`notes.md` 建议 + 交互指南 §9 T4 假设"MVP 先用纯 TextField + 格式化按钮（MVP），语法高亮后置"。项目无第三方 UI 框架（`ui-framework.md` §一），引入 `code_text_field`/语法高亮包需评估依赖成本，非 MVP 必需。

**实现方案**：
- 高级模式视图：`TextField(maxLines: null, style: 等宽, controller: 绑 JSON 文本)` + footer 按钮：
  - 「格式化」：`jsonEncode(jsonDecode(text), indent: 2)` 回填。
  - 「应用并切回可视化」：`jsonDecode` → 失败则 SnackBar 提示"JSON 解析失败，已停留在高级模式"（AC-15）；成功则重建 `EditableLessonModel` 并切回。
  - 「校验」：走 `LessonValidator`。
- 状态管理：高级模式文本与可视化模型**单一数据源**为 `EditableLessonModel`；切到高级模式时由模型 `toJson()` 序列化出文本，切回时重新解析回填模型（避免双写漂移）。

**影响面**：`lesson_editor/panels/lesson_footer_bar.dart` 内嵌高级模式视图（或独立 `lesson_editor/screens/json_editor_view.dart`）。无新依赖。

### 3.5 T5 · 冲突规则表——**配置化 `sim_conflict_rules.json` + 失败降级**

**结论**：**冲突规则存 `assets/editor/sim_conflict_rules.json`（allowedCombos + warnCombos），加载失败降级为"仅数据传递冲突检查"（不 crash）**。与 T2 刷新联动（进入加载 + 刷新按钮同步刷新）。

**依据**：交互指南 §4.5 + §9 T5 已拍板 + C7/C8/C9（警告级 · 配置化 · 不破坏已验收组合）。

**实现方案**：
- 规则文件结构（交互指南 §4.5 §4.5 定义）：
  ```json
  {
    "version": "1",
    "allowedCombos": [["circuit", "color_vision"]],
    "warnCombos": [
      {"from": "forces", "to": "circuit", "reason": "力学与电路教学衔接需人工确认"}
    ]
  }
  ```
- `ConflictRuleSet` 模型（L1 候选）：`rootBundle.loadString` → `jsonDecode` → 解析 allowedCombos/warnCombos；任何异常 → 返回"降级态"（`isDegraded=true`，仅数据传递检查）。
- 加载时机：进入编辑器 `initState` + 「刷新场景列表」按钮旁同步刷新（与 T2 联动）。
- 未知组合（不在 allowed 亦不在 warn）→ **保守放行不报错**（交互指南 §4.5），提示可在规则表显式声明。
- `allowedCombos` 默认含 `["circuit","color_vision"]` → 已验收 `cross-sim-explore`（AC-58 同型）零警告（AC-21）。

**影响面**：新增 `assets/editor/sim_conflict_rules.json` + `lesson_editor/conflict/` 两文件。规则表由 AI 生成/手工编辑（C8 · AI 可生成化）。

## 4. 新增 sim 接线 4 处清单（支撑 T2 动态刷新）

## 5. 编辑器数据模型设计（可编辑态 ↔ LessonPlan JSON 双向映射）

### 5.1 `EditableLessonModel`（@immutable + copyWith）

编辑器需要一个**可编辑态模型**，与运行时 `LessonPlan`（不可变解析产物）解耦——因为编辑过程常有**中间态**（如"未配 advance 的非终点节点"在 `LessonPlan.fromJson` 会 fail loud，但在编辑态允许暂存）。

```dart
@immutable
class EditableNode {
  final String id;
  final String title;
  final LessonScenarioRef? scenario;      // 复用运行时值对象
  final SuccessCondition? unlock;         // 复用运行时条件树
  final LessonAdvance? advance;           // 复用运行时值对象
  final bool isEndNode;                   // 终点节点（scenario==null）
}

@immutable
class EditableLessonModel {
  final String lessonId;
  final String name;
  final String version;
  final String description;
  final String? entry;                    // 可空：新建态尚未指定
  final List<EditableNode> nodes;
  final Map<String, Offset> layout;       // 节点id → 画布屏幕坐标（editor-only）
  // copyWith + toLessonPlanJson() + fromLessonPlanJson()
}
```

### 5.2 与 LessonPlan JSON 的映射

- **保存/导出**：`EditableLessonModel.toLessonPlanJson()` 只序列化 schema 字段（lessonId/name/version/description/entry/nodes），产出与运行时 `cross-sim-explore.json` 完全同构 → 交给 `LessonPlan.fromJson(scenarioPlayable: LessonSimHosts.scenarioPlayable())` 端到端校验（AC-13）。
- **导入**：`EditableLessonModel.fromLessonPlanJson(json)` 解析运行时 JSON → 节点映射为 `EditableNode` + 布局读 `.layout.json`（T3）。
- **中间态容错**：`EditableNode` 允许 `advance == null` 的中间态（前端编辑未完成时），仅保存前经 `LessonValidator` 强制补齐（复用 `LessonPlan.fromJson` 的 9 图校验 + schema）。

### 5.3 序列化源

运行时值对象已具备 `toJson()`：`SuccessCondition.toJson()`（`success_condition.dart:111`）/ `LessonNode` 的 schema 字段。编辑器序列化直接组装这些值对象的 JSON，**零重复实现**。

## 6. 冲突检测算法（F14 · 两类）

### 6.1 输入

- 已解析的剧本图（`List<EditableNode>` + advance 拓扑）。
- `ConflictRuleSet`（T5 规则表，可降级）。

### 6.2 第一类 · 教学语义冲突（sim→sim 组合）

遍历**所有有向边**（由 advance 产生：`next`→数组中后继 / `onCompleted`→to / `routes`→全部 to；终点无边）：

```
对每条边 (fromNode → toNode)：
    if fromNode.scenario == null || toNode.scenario == null: continue  // 终点无边语义
    from = fromNode.scenario.sim
    to   = toNode.scenario.sim
    if from == to: continue  // 同 sim 不查
    if {from,to} ∈ allowedCombos（无序）: continue          // 白名单放行（AC-21）
    if (from→to) ∈ warnCombos（有序）: 记警告 reason        // 教学语义冲突
    else: 未知组合 → 保守放行不报错（提示可显式声明）
```

### 6.3 第二类 · 数据传递冲突（跨 sim 条件树叶子引用）

遍历每个节点的 `unlock` 与 routes 各 `when` 的条件树叶子（`SuccessCondition.collectLeaves()`）：

```
对每个节点的条件树叶子 leaf：
    if leaf.type ∈ {nodeCompleted, predictionScore}:
        nodeId = leaf.params['nodeId']
        if nodeId 对应节点存在 且 node.scenario.sim != 当前节点.scenario.sim:
            记数据传递冲突（跨 sim 引用）
    if leaf.type == scenarioSuccess:
        nodeId = leaf.params['nodeId']  // 可选；提供时同样查跨 sim
```

> 依据：`LessonPlan.fromJson` 规则 8（`lesson_plan.dart:184-216`）已校验叶子 nodeId 存在性；此处补"跨 sim"语义。运行时求值本已 fail-safe（`lesson_runtime.dart:88-110` 引用不存在/未完成 → false），故数据传递冲突是**警告级**（C7）不产生运行时错误。

### 6.4 输出

- `ConflictChecker.analyze(EditableLessonModel) → List<ConflictWarning>`，每条含：`type`（semantic/dataFlow）、涉及节点/边、`reason`。
- 画布标注：冲突边 → 黄虚线 + 警告图标；冲突节点 → 右上角黄色 ⚠ 角标（AC-19）。
- 保存时：`LessonValidator` 通过后，若存在 warning 列表 → 弹确认框列全部警告（"N 项警告：…"）→「仍要保存」/「取消」（C7 不阻止）。

### 6.5 与 AC-21 的关系

`allowedCombos` 默认含 `["circuit","color_vision"]` → 任意 circuit↔color_vision 双向边（无论方向/顺序）→ 白名单放行零警告。已验收 `cross-sim-explore`（circuit→color_vision→circuit，见 §5.3 示例 JSON）不会误报。

## 7. 校验 / 导入导出 / 高级 JSON 方案

### 7.1 校验（F8 · AC-9/AC-12）

`LessonValidator.validate(EditableLessonModel)`：
1. 序列化 `toLessonPlanJson()` → **schema 校验**（`schemas/lesson.schema.json`，Dart 侧实现 `additionalProperties`/enum/oneOf 判定，或 `json_serializable` + 手写断言；本项目无 json schema 运行时依赖，需轻量自实现或复用工具层）。
2. **复用 `LessonPlan.fromJson(scenarioPlayable: LessonSimHosts.scenarioPlayable())` 的 9 图校验**（fail loud）——捕获未达 9 条规则即给出错误（节点 id 重复 / entry 悬空 / 终点二元绑定 / advance 非法 / routes 兜底 / 叶子悬空 / 图不可达 / 场景不可玩）。错误信息带 `lessonId` 前缀（`lesson_plan.dart:105-106`）。
3. 结果含：`errors`（阻止保存）+ `warnings`（冲突警告清单，不阻止）。
4. 画布反馈：错误项定位到节点（红圈）/置灰不可达节点（交互指南 §6.1）。

### 7.2 导入（F9 · AC-10/AC-11）

- 「导入」→ 文件选择器（复用 `assets/lessons/*.json` 路径，本项目无文件选择器 L0，需用 `file_picker` 或限定 `assets/lessons/` 内选——MVP 建议限定内置目录内选择，避免新依赖）。
- 解析：`jsonDecode` → `LessonPlan.fromJson`（先校验合法性）→ 成功映射 `EditableLessonModel` + 读 `.layout.json` 布局 → 画布还原。
- 失败：弹窗报错，停留在空画布/上次编辑态，不 crash（交互指南 §7 降级）。

### 7.3 导出/保存（F10 · AC-12/AC-13）

- 保存 → 写 `assets/lessons/<lessonId>.json`（schema 契约）+ `<lessonId>.layout.json`（T3）+ 更新 `assets/lessons/manifest.json`（lessons 数组增/覆盖）。
- 失败兜底：写入失败 SnackBar 错误，编辑态内存保留可重试（交互指南 §6.2）。
- 端到端闭环：保存产物 `LessonPlan.fromJson` 通过 → `LessonRuntime.load()` 可加载（AC-13）。

### 7.4 高级 JSON 模式（F12 · AC-14/AC-15）

见 §3.4（T4）。单一数据源 `EditableLessonModel`，切换时序列化/回解析。

| # | 风险 | 缓解 |
|---|---|---|
| R1 | **T1 连线画布架构级新增**——拖手柄→目标、分叉路由可视化、冲突边标注，交互复杂度高 | 先用最小 `LessonCanvasView`（线性 next/onCompleted）跑通 AC-2/AC-3，再迭代 routes 分叉；`LessonEdgePainter` 严格遵循 CustomPainter 范式（构造注入 + 引用比较 shouldRepaint） |
