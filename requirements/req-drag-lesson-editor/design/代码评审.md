## 四、Major（强烈建议修）

- [ ] **M1（AC-10 / T3 偏离）** `lib/lesson_editor/validation/lesson_importer.dart:100-123`（`_readLayout`）+ `lib/lesson_editor/canvas/lesson_canvas_view.dart:99-100`
  技术方案 §3.3（T3）承诺："`.layout.json` 缺失/损坏 → 降级走 `LessonAutoLayout`（层流自动布局：entry 起 BFS，按 level 横向排布）"。但实际实现中 `_readLayout` 遇到缺失/损坏直接返回 `const {}`（空 Map），画布渲染时用硬编码 `left: layout[node.id]?.dx ?? 40, top: ... ?? 40` 兜底——**所有缺失布局信息的节点会重叠堆叠在同一坐标点 (40,40)**，而非分散排布。
  这个降级路径对应的正是 AC-10 提到的"含 AI 生成产物"这一**核心场景**（AI 生成的 lesson JSON 天然没有配套 `.layout.json`），并非边缘情况。方案清单中登记的 `lesson_auto_layout.dart`（L1 候选）也从未创建。
  测试 `lesson_importer_test.dart:74-89` 的用例名为"自动布局兜底"，但断言内容只验证 `layout` 为空 Map "不 crash"，并未验证任何"自动布局算法"效果，未能暴露此问题。
  **建议改法**：按方案实现最小 BFS 层流布局算法（entry 起分层，每层横向等距排布），至少让多节点导入后可视觉区分。

- [ ] **M2（AC-19 / T21 部分未实现）** `lib/lesson_editor/canvas/lesson_node_card.dart` / `panels/condition_tree_editor.dart`
  任务清单 T21 明确要求"冲突节点⚠角标"+"条件树内跨 sim 叶子标黄"。实际实现中，`LessonNodeCard` 没有任何冲突角标渲染逻辑（无 `isConflict` 参数），`ConditionTreeEditor` 没有对跨 sim 叶子做视觉标黄。**仅 semantic 类型的冲突边在 `LessonEdgePainter` 中有黄虚线标注**（`lesson_edge_painter.dart:82-91`），dataFlow 类型冲突（条件树叶子跨 sim 引用，本身不对应画布上的一条边）在画布上**没有任何可视化标记**——用户只能通过点击"保存"弹出的确认框文字清单才能发现该类警告。
  需求 AC-19 原文"画布存在 sim 冲突时给出可视化警告标记"，目前只有一半（semantic 边）达成。
  **建议改法**：`LessonNodeCard` 增加冲突节点⚠角标（Screen 层传入受影响的 dataFlow 冲突节点 id 集合）；`ConditionTreeEditor` 对涉及跨 sim 引用的叶子项做黄色高亮。

- [ ] **M3（AC-7 数据一致性 bug）** `lib/lesson_editor/panels/advance_editor.dart:108-161`（`_buildRoutesEditor`/`_RouteRow`）
  routes 末项 UI 上隐藏了条件编辑器（`isLast` 时不渲染 `ConditionTreeEditor`），但**当用户删除当前末项路由后，原倒数第二条自动"晋升"为新末项时，其 `when` 字段的旧数据并未被自动清空为 `null`**。因为 `onRemove` 只是 `[...routes]..removeAt(i)`，不触碰其余条目字段。
  这会导致：若某条路由曾经有条件（when != null），之后因删除末项而"被动"变为新末项，保存时会触发 `LessonPlan.fromJson` 规则 6 校验失败（"routes 缺兜底路由（末项 when 必须为 null）"），而**用户在 UI 上无法修复**——因为 `isLast` 分支不渲染条件编辑区，没有任何入口可以把这条路由的 `when` 清空（唯一出路是切到高级 JSON 模式手工改，对非技术教师用户几乎不可用）。
  此问题未被任何单测覆盖（`lesson_validator_test.dart`/`advance_editor` 均无对应用例）。
  **建议改法**：`onRemove` 时若剩余 routes 非空，强制把新末项的 `when` 置为 `null`（`routes[routes.length-1]` 的 `when` 清空）；同时在 `isLast` 分支即使不显示条件编辑器，也应保证数据层已被清空，不依赖用户手动操作。
