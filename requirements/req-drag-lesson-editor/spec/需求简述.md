# 需求简述：拖拽式编排 sim 剧本（作者侧可视化编排）

> **需求 ID**: req-drag-lesson-editor  
> **SOP**: agile-vibe  
> **版本**: v1.0（2026-08-26）  
> **状态**: 需求定义完成

---

## 1. 背景

lesson-runtime（req-lesson-runtime）已完成运行时实现（P1 线性 + P2 条件分支 + P3 AI 生成链路），但其 C-R5 明确排除"作者侧可视化编排 UI"（S2）。当前课时剧本的创建路径仅有：手写 JSON 或 AI 生成（generate.py --lesson）——对非技术背景的教师/课程设计者不友好。

本需求补上该缺口：在 kratosLab Flutter App 内提供**拖拽式可视化编排界面**，让作者可以直观地创建和编辑符合 `lesson.schema.json` 的课时剧本。（S1, S2, S6）

---

| # | 目标 | 来源 |
|---|------|------|
| G1 | 教师/课程设计者可在 App 内通过拖拽节点、连线方式编排 sim 衔接顺序与剧本流程 | S1 |
| G2 | 产出的剧本 JSON 严格符合 `schemas/lesson.schema.json`，可被 LessonRuntime 直接消费 | S6, S7 |

## 5. 约束与假设

### 5.1 约束

| # | 约束 | 来源 |
|---|------|------|
| C1 | 编辑产物必须走 `assets/lessons/*.json` + `schemas/lesson.schema.json`（与 AI 生成链路共用同一数据契约） | S6 |
| C2 | 复用 L0 组件（DragDropWorkspace / PropertyControlPanel），禁止平行实现同类组件 | S6, S8 |
| C3 | 向后兼容 req-lesson-runtime 运行时——编辑器产出的 JSON 必须可被现有 LessonRuntime 消费 | S6 |
| C4 | 编排范围限定为现有 lesson.schema.json 定义的结构，不引入新原语 | 用户答复 Q2 |
| C5 | 条件树叶子封闭枚举：nodeCompleted / predictionScore / scenarioSuccess（与运行时一致） | S7 |
| C6 | 场景引用限定为已有 sim manifest 中注册的场景（T2 已拍板：注册表驱动 + 动态刷新，新增 sim 接线 4 处后自动出现在选择器，无需重启） | S7 |
| C7 | 冲突规则为**警告级**，不阻止保存（作者可自行承担风险） | 用户 2026-08-26 拍板 |
| C8 | 冲突规则来自**配置化规则表**（JSON），遵循项目配置化/AI 可生成化路线 | 用户 2026-08-26 拍板 |
| C9 | 规则表默认放行已验收的 circuit↔color_vision 组合（不破坏 AC-58 混合剧本） | 用户 2026-08-26 拍板 |

## 6. 技术待确认项

| # | 问题 | 影响范围 |
|---|------|---------|
| T1 | DragDropWorkspace 当前为"元件拖入画布"场景设计，用于"节点图/流程图"编排是否需要显著扩展或用其他方式实现节点连线？ | 架构方案选择 |
| T2 | lesson.schema.json 中 scenarioRef.sim 当前 enum 为 `["circuit", "color_vision"]`（试点封闭集），编辑器是否应动态读取实际 manifest 而非硬编码 | 场景选择器实现 |
| T3 | 节点画布布局位置信息如何持久化？lesson JSON 无此字段。选项：a) 扩展 schema 加 metadata 字段；b) 单独 .layout.json 文件；c) 每次打开自动布局 | 导入/导出闭环 |
| T4 | 高级 JSON 模式的编辑体验——是否需要语法高亮、JSON 格式化等能力，Flutter 内嵌文本编辑器的可行性 | 交互实现 |
