## 1. 用户使用场景

### 场景 A：物理老师从零编排一节课（核心场景 · 非技术用户）

王老师想上一节"电路 + 色觉"综合课：学生先搭一个串联电路点亮灯泡，再去做 RGB 色光混合，最后完成挑战题。

1. 打开 App → 首页顶部点「剧本编辑器」入口
2. 点「新建剧本」→ 填课时名"电与光的探索"（自动生成 lessonId / version）
3. 从左侧「节点库」拖入 3 个节点，分别选择场景：
   - 节点 1：电路 → simple-series（串联灯泡）
   - 节点 2：色觉 → rgb-default（RGB 混合）
   - 节点 3：色觉 → rgb-cyan-challenge（挑战）
4. 依次连线 1→2→3，拖入终点节点，连线 3→终点
5. 点第 3 个节点 → 属性面板「流转方式」选「条件路由」，加两条路由：
   - "预测全对"→ 终点（when: predictionScore ≥ 3）
   - "否则"→ 节点 2 重做（兜底）
6. 点「校验」→ 全部通过 → 点「保存」→ 剧本进入课时列表

**结果**：首页电路组出现「电与光的探索」课时卡片，点击即可开课。全程无 JSON 接触。

### 场景 B：开发者用 AI 生成剧本后微调（高级用户 · 导入路径）

李老师用 `generate.py --lesson` 生成了一份剧本 JSON，想微调分支逻辑：

1. 进入「剧本编辑器」→「导入」→ 选择 `electric-light.json`
2. 画布自动布局还原节点与连线
3. 点某节点 → 属性面板 → 条件路由里改阈值（预测题 ≥ 2 分改 ≥ 3 分）
4. 或切「高级 JSON 模式」，直接改 `threshold` 字段后切回可视化
5. 「校验」通过 → 「另存为」→ 新剧本入库

### 场景 C：教研员审阅既有剧本（只读/检查场景）

1. 「剧本编辑器」→「导入」既有剧本
2. 只看不动：画布直观展示节点流程，`unlock` 门禁用锁图标标注，条件路由用分叉线标注
3. 发现某节点标红（校验错误：场景引用已不存在）→ 用场景选择器改指到有效场景 → 保存

| 格子 | 内容 | 对应功能点 |

## 3. 编排画布交互（F2/F3 · 核心）

### 3.1 节点形态

| 节点类型 | 卡片视觉 | 数据绑定 |
|---|---|---|
| 普通场景节点 | 白卡 + sim 主题色图标 + 标题 + 场景名（如 "电路搭建 · simple-series"） | `LessonNode{scenario}` |
| 终点节点 | 灰卡 + 旗帜图标 + "课时完成" | `LessonNode{scenario: null, advance: null}` |
| 入口节点 | 普通节点上叠绿色「入口」角标 | `plan.entry == node.id` |
| 锁定节点 | 卡片左上锁图标（有 unlock 条件） | `node.unlock != null` |

### 3.2 拖拽编排

- **添加节点**：从 midLeft 托盘拖 `DragItemCard` 到画布 → 落点生成新节点卡片（复用 `DragDropWorkspace` 的 `DropCanvas.onItemDropped` 机制，T1 适配）
- **移动节点**：画布内拖拽节点卡片 → 位置实时更新（卡片为 `Draggable`，画布底层 `GestureDetector` 处理）
- **连线（流转）**：节点卡片右下角拖出连线手柄 → 拖到目标节点卡片上松开 → 生成 `advance` 连线（T1 关键新增：现有 DragDropWorkspace 无连线能力，迭代首轮验证）
- **删除节点/连线**：选中后点 footer「删除」或按 Del 键；删除节点时其入/出连线一并清理

### 3.3 连线视觉与语义（映射 advance 三型）

| advance 类型 | 连线呈现 | 说明 |
|---|---|---|
| `next` | 实线箭头 节点→数组下一节点 | 默认类型，拖入节点自动生成 |
| `onCompleted` | 实线箭头（标注"完成后"） | 场景完成即流转 |
| `routes` | 分叉线：一条主干 + N 条支线，各标条件名 | 支线末项为兜底（when=null） |
| 终点 | 指向终点节点的实线 | 无出线 |

> 连线的"目标端"是用户手动连出来的；`next` 型在连线后自动把 `advance.to/routes` 写成目标节点 id。类型与字段的映射校验交给 F8。

## 4. 属性编辑交互（F4/F6/F7/F13）

> 面板组件：`PropertyControlPanel` + `KratosComboBox` / `KratosRadioGroup` / `KratosNumberField` / `KratosSlider`（L0 复用，禁平行实现）[来源: lib/common/widgets/property_control_panel.dart:19-27]

### 4.1 节点属性（选中普通节点）

| 字段 | 控件 | 规则 |
|---|---|---|
| 标题 title | 文本框 | 必填 |
| 场景引用 | sim 下拉 + scenarioId 下拉（二级联动） | 只允许选已注册 sim + manifest 中存在的场景（F5 · T2）· **动态加载 + 手动刷新按钮**（见 §4.1.1） |
| 解锁条件 unlock | 「+ 添加解锁条件」→ 条件树编辑器 | 可选；添加后节点显示锁图标 |
| 流转方式 advance | RadioGroup: 顺序流转(next) / 完成后跳转(onCompleted) / 条件路由(routes) | 切换时动态显示对应字段（AC-6） |
| — to（onCompleted） | 目标节点下拉 | 必填；只列画布已有节点 |
| — routes（条件路由） | 路由列表编辑：每行 = 条件名 + 目标节点下拉；「+ 添加路由」 | 末项自动标记"兜底路由"（when=null），不可设条件（AC-7） |

### 4.1.1 场景选择器动态刷新（用户拍板 · 2026-08-26）

- **数据源**：动态读 `LessonSimHosts` 已注册 sim + 各 sim `ScenarioManager` 的场景清单（T2 落定：非硬编码 enum，走注册表驱动）
- **刷新机制**（新增 sim 后编辑时能立即选到）：
  1. **进入编辑器时**：每次打开编辑器重新执行 `ensureManagersLoaded()`（幂等）+ 重新读各 sim 场景清单——不缓存死，跨会话必新
  2. **编辑器内手动刷新**：场景选择器旁提供「刷新场景列表」图标按钮（`Icons.refresh_rounded`）——编辑会话中新增 sim 后点一下即可看到新 sim 及其场景，无需退出重进
- **新增 sim 的接线要求**（编辑侧只管"读到什么显示什么"，接线在运行时侧，4 处手工改动见 §9.1）：
  - 接线后 → 场景选择器下拉自动出现该 sim（满足"刷新出来"）
  - 未接线 → 下拉不出现（`scenarioPlayable` 返回 false 的 sim 不在候选列表）

### 4.2 终点节点属性

- 显示"本节点为课时终点，无流转指令"说明（二元绑定 D5 可视化告知）

### 4.3 条件树编辑器（F7）

用于 unlock 与 routes.when，层级化表单：

```
[全部满足 all] / [任一满足 any] / [取反 not]   ← 组合节点
    └── 叶子条件：类型下拉 + 参数表单
```

| 叶子类型 | 参数 | 例子 |
|---|---|---|
| nodeCompleted | 目标节点下拉（nodeId） | "完成节点 n2" |
| predictionScore | 节点 + metric + operator(≥/>/≤/<) + threshold | "节点 n2 预测分 ≥ 3" |
| scenarioSuccess | 节点下拉（可选，缺省=当前节点） | "场景成功" |

- 支持嵌套（组合节点内再套组合），深度上限 4（`SuccessCondition.maxParseDepth`）
- 「+ 添加叶子」「+ 添加子组合」「删除」按钮逐层构建
- 条件树 JSON 与 `schemas/lesson.schema.json` 的 lessonCondition 严格同构 [来源: lib/common/scenario/success_condition.dart:30-100]

### 4.4 剧本元数据（F13）

顶部「剧本设置」面板：lessonId（生成建议 + 可改）/ name / version / description / entry 节点下拉（只列画布已有节点）。

### 4.5 上下游 sim 冲突检测（F14 · 用户 2026-08-26 拍板）

#### 冲突的两类判定（对应需求简述 AC-20）

| 类型 | 判定依据 | 示例 |
|---|---|---|
| **教学语义冲突** | 规则表中的 sim→sim 组合标记（如"力学↔电路无衔接铺垫"） | 上游 forces 节点 → 下游 circuit 节点 |
| **数据传递冲突** | 条件树叶子（nodeCompleted/predictionScore/scenarioSuccess）的 `params.nodeId` 引用了**不同 sim** 的节点 | circuit 节点 unlock 条件引用 color_vision 节点完成态 |

#### 规则来源与配置化（C8 · AC-18）

- 冲突规则存于独立 JSON 规则文件（如 `assets/editor/sim_conflict_rules.json`），结构示例：
  ```json
  {
    "version": "1",
    "allowedCombos": [["circuit", "color_vision"]],
    "warnCombos": [
      {"from": "forces", "to": "circuit", "reason": "力学与电路教学衔接需人工确认"}
    ]
  }
  ```
- 遵循项目配置化 / AI 可生成化路线：规则表可由 AI 生成、手工编辑，编辑器加载失败降级为"仅数据传递冲突检查"（不 crash）
- 规则表加载时机：进入编辑器时加载 + 「刷新场景列表」按钮旁同步刷新（与 T2 联动）

#### 警告呈现（C7 · AC-19）

| 位置 | 呈现 |
|---|---|
| 画布连线 | 冲突连线变黄色虚线 + 警告图标 |
| 节点 | 涉及冲突的节点右上角黄色 ⚠ 角标 |
| 属性面板 | 条件树内引用跨 sim 节点的叶子标黄 |
| 保存时 | 弹确认框列出全部警告清单（"N 项警告：……"）→「仍要保存」/「取消」 |

> 警告**不阻止保存**（C7）：作者确认后仍可保存运行——运行时对条件树叶子引用按现有 fail-safe 语义求值（引用不存在/未完成 → false），不产生运行时错误 [来源: lib/common/scenario/lesson_runtime.dart:88-110]。

#### 与已验收混合剧本的关系（C9 · AC-21）

- 规则表 `allowedCombos` 默认含 `["circuit", "color_vision"]` → 现有「电与光的探索」混合剧本（AC-58 同型）零警告
- 未在 allowedCombos 且未在 warnCombos 的组合 → 默认视为"未知组合"：不报错（保守放行），提示可在规则表中显式声明

## 5. 完整操作流程

### 流程 1：从零新建（对应场景 A）

1. 首页 → 「剧本编辑器」
2. footer「新建」→ 填元数据（或默认值）→ 空白画布
3. 拖入普通节点 → 弹属性面板（或随后选中编辑）→ 选 sim + 场景
4. 重复步骤 3 直到所有场景节点就位
5. 拖入终点节点
6. 连线：按期望流转顺序连接各节点 → 终点
7. 需要分支的节点：属性面板改「条件路由」→ 添加路由 + 条件
8. 需要门禁的节点：属性面板「+ 添加解锁条件」
9. topRight「校验」→ 看结果（通过 / 列出错误项并定位到节点）
10. 全通过 → 「保存」→ 写入 `assets/lessons/<id>.json` + 更新 manifest → SnackBar "剧本已保存"

### 流程 2：导入修改（对应场景 B）

1. 首页 → 「剧本编辑器」→ footer「导入」
2. 文件选择器 → 选择 `assets/lessons/*.json`
3. 解析 + 自动布局（T3）→ 画布还原
4. 按需编辑（同流程 1 的 6-9）
5. 「另存为」→ 新 lessonId 入库，或「保存」覆盖原文件

### 流程 3：校验失败处理（对应场景 C 的异常路径）

- 校验结果面板列出每条错误（如 "节点 n2 引用场景不可用"、"存在从 entry 不可达的节点"）
- 点击错误项 → 画布高亮对应节点（红圈）
- 修复后重新校验；不通过不允许保存

## 6. 校验与保存（F8/F10）

### 6.1 校验规则（保存前强制）

复用 `LessonPlan.fromJson` 的 9 条图校验 + schema 校验 [来源: lib/common/scenario/lesson_plan.dart:95-251]：

| 规则 | 错误示例 | 画布反馈 |
|---|---|---|
| 顶层字段齐全 | 缺 name | 顶部元数据面板标红 |
| 节点 id 唯一 | id 重复 | 重复节点红圈 |
| entry 存在 | entry 指向不存在节点 | 入口标红 |
| 终点二元绑定 | 终点节点带 advance | 节点红圈 + 提示 |
| advance 三型合法 | 非法 type | 属性面板报错 |
| routes 末项兜底 | 兜底不在末项 | 路由列表报错 |
| unlock 叶子引用存在 | 叶子 nodeId 悬空 | 条件树内标红 |
| 图可达性 | 某节点从 entry 不可达 | 不可达节点置灰 + 提示 |
| 场景可玩性 | 引用场景不存在/不可完成 | 场景选择器红色边框 |

### 6.2 保存动作

- 「保存」：写 `assets/lessons/<lessonId>.json` + 更新 `manifest.json` 的 lessons 数组（新增/覆盖）
- 失败兜底：写入失败 → SnackBar 错误信息，不丢编辑态（编辑态内存保留，可重试）

## 7. 边界与降级

| 场景 | 行为 |
|---|---|
| 导入损坏 JSON | 解析失败 → 弹窗报错 → 停留在空画布/上次编辑态，不崩溃 |
| 导入后布局还原 | 自动布局生成初始位置（T3 选型后确定：外置 .layout.json 或纯自动） |
| 窄视口 | 托盘/属性面板收为抽屉，画布保持 ≥70% 面积 |
| 删除被引用的节点 | 引用它的连线/条件树叶子同步清理；清理后若违反图校验 → 校验提示 |
| 高级 JSON 模式修改非法 | 切回可视化时解析失败 → 提示"JSON 解析失败，已停留在高级模式"（AC-15） |
| 无 undo/redo | MVP 不实现（A3 · [基于假设]），删除节点前弹确认 |

### 9.1 新增 sim 接入清单（方案 A · 注册表驱动）

新增一个 sim 进剧本能力（如 forces），需在运行时侧接线 **4 处**（编辑侧零改动，接线后自动出现在场景选择器）：

| # | 位置 | 改动 |
