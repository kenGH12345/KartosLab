## 1. 两套投影公式对比（T1 决策依据）

### 1.1 现状定义

**CanvasProjection**（lib/common/widgets/drag_drop_workspace.dart:16-22）：

```dart
class CanvasProjection {
  final Size canvasSize; final double scale;
  CanvasProjection({required this.canvasSize, this.scale = 1.0});
  Offset get origin => Offset(canvasSize.width / 2, canvasSize.height * 0.55); // ← getter 硬编码
  Offset toScreen(Offset w) => Offset(origin.dx + w.dx * scale, origin.dy + w.dy * scale);
  Offset toWorld(Offset s) => Offset((s.dx - origin.dx) / scale, (s.dy - origin.dy) / scale);
}
```

**SceneProjection**（circuit_canvas.dart:5-11 与 circuit_screen.dart:1156-1172 逐行等价，仅格式差异）：

```dart
class SceneProjection {
  final double scale; final Offset origin; final double zoom;
  const SceneProjection({required this.scale, required this.origin, this.zoom = 1.0});
  Offset toScreen(Offset w) => Offset(w.dx*scale*zoom+origin.dx, w.dy*scale*zoom+origin.dy);
  Offset toWorld(Offset s) => Offset((s.dx-origin.dx)/(scale*zoom), (s.dy-origin.dy)/(scale*zoom));
  double toScreenLength(double w) => w*scale*zoom;
}
```

### 1.2 差异矩阵

| 维度 | CanvasProjection | SceneProjection | 统一策略 |
|------|-----------------|-----------------|---------|
| origin | getter 硬编码 `(w/2, h*0.55)`（:19） | 构造注入（circuit 传 `(w/2, h/2)`，circuit_screen.dart:910） | **构造注入**（参数化，AC-1 明确要求） |
| 有效比例 | `scale` | `scale × zoom` | 保留双字段（语义不同：scale=世界单位换算，zoom=用户交互缩放），乘积为有效比例 |
| zoom | ❌ | ✅（默认 1.0） | 可选参数，默认 1.0（AC-1/A2） |
| toScreenLength | ❌ | ✅（circuit CircuitPainter 依赖，circuit_screen.dart:967-968） | 保留 |
| canvasSize | ✅ 字段（optics 依赖 `projection.canvasSize`，optics_screen.dart:545-546） | ❌ | **不进投影类**（见 §4.3：canvasBuilder 改带 size 参数） |

**数学本质**：两者是同一个仿射变换 `screen = world × k + origin`，仅 k 的分解方式（`scale` vs `scale×zoom`）与 origin 来源不同。**不存在公式级分歧，无多态需求**。

### 1.3 T1 决策：单一具体类 + 参数化（不用抽象基类）

**决策**：统一为**一个具体类 `SceneProjection`**，放 `lib/common/geometry/projection.dart`，参数 `origin`（必填）+ `scale`（默认 1.0）+ `zoom`（默认 1.0）。

**理由**：

1. **两实现 100% 同构**（§1.2）：抽象基类的价值在于子类有不同行为实现，而这里两个"子类"只是同一公式的参数差异。抽象基类 + 两个子类（如 `OpticsProjection`/`CircuitProjection`）= 用继承表达参数，属于过度设计，违反 shared-abstraction-plan 核心原则"通用的抽到 common，特有的不硬塞"（[来源: docs/knowledge/kratos-java-simulations/shared-abstraction-plan.md:4]）。
2. **先例对齐**：候选 1 `PositionElement` 用抽象类是因为子类真有多态（4 光学子类 + 电路元件 + 抽象 getter 两种实现方式，shared-abstraction-plan.md:40-44）；投影类没有第二形态，不满足抽象的结构性理由。
3. **API 稳定性**：单一具体类 + 具名参数的签名对未来 sim（sound/wave-interference 等）零学习成本；若未来出现真正的第二投影形态（如带旋转），届时再抽基类不迟（3-Time Rule 同样适用于"抽象程度"）。

**命名**：沿用 `SceneProjection` 而非 `Projection`/`CanvasProjection`。理由：统一类的行为超集 = SceneProjection（origin 注入 + zoom + toScreenLength 都是它先有）；"场景投影"（world↔screen）语义比"画布投影"准确；circuit 侧 3 个文件的类型引用可零语义负担保留。

**子路径**：新建 `lib/common/geometry/`。依据：项目已有"非 widget 基础类型放专属子目录"模式（`common/elements/position_element.dart` 先例，shared-abstraction-plan.md:46）；投影是几何概念，不是 widget，放 `common/widgets/` 语义不符；与 T2 的 `hit_test.dart` 同目录成组。

## 2. T2 决策：`_hitTestWire` 上抽为纯几何函数

### 2.1 两份实现对比（含行为差异澄清）

| | circuit_canvas.dart:135-164（死代码） | circuit_screen.dart:1057-1082（生效版） |
|---|---|---|
| 签名 | `_hitTestWire(Offset wp, SceneProjection proj, {double threshold = 15})` | `_hitTestWire(Offset wp, SceneProjection proj)` |

### 2.2 决策：`lib/common/geometry/hit_test.dart` 纯函数，不进 PositionElement 体系

**上抽粒度**：只抽**几何原子** `pointToSegmentDistance(Offset p, Offset a, Offset b)`，**不抽**"遍历 wires + findVertex + 返回 index"的整段逻辑。

**理由**：

1. **导线不是 PositionElement**：导线是 `WireSegment`（controlPoints）+ `Vertex` 体系（circuit_state.dart，circuit_screen.dart:1059-1068 消费），与 `PositionElement<TType>`（id/x/y/width/height 矩形命中，position_element.dart:17-44）是**两个域模型**。把线段命中塞进"位置元件基类"违反其文档声明的设计边界（"域特化行为不上抽"，position_element.dart:11-12）与单一职责。
2. **分层对齐**：知识库明确"命中检测在 Screen 层用世界坐标/屏幕坐标，不在 Painter 内"（[来源: docs/knowledge/kratos/frontend/ui-framework.md:27]）。`_hitTestWire` 的调用编排（先元件后导线的顺序、阈值取值、返回 index 语义）是 **circuit Screen 层的交互策略**（L2 域逻辑，留在 circuit_screen.dart 唯一一处）；而点-线段距离是与域无关的几何计算（可上抽，坐标经投影转屏幕后判定，两份实现都在屏幕坐标系做距离）。
3. **spec §2 目标 3 要求上抽公共层**：`pointToSegmentDistance` 纯函数、零域依赖、零状态，是上抽的最小完整单元。

## 3. T3 决策：DropCanvas 增加**投影工厂回调**（根治 workaround）

### 3.1 方案比选

| 方案 | 描述 | 评估 |
|------|------|------|
| **A. 工厂回调（采纳）** | `DropCanvas` 新增可选参数 `projectionFactory: SceneProjection Function(Size canvasSize)?`；null 时默认 `(sz) => SceneProjection(origin: Offset(sz.w/2, sz.h*0.55), scale: scale)`（即旧 CanvasProjection 语义） | ✅ circuit 传工厂后，canvasBuilder 与 onAcceptWithDetails 用**同一投影实例**，workaround 整体删除；optics 不传工厂 = 行为严格不变（默认工厂保留 0.55）；投影实例无法在 Screen 层提前构造（DropCanvas 用 LayoutBuilder 拿尺寸，drag_drop_workspace.dart:129-131），工厂是唯一能"外部定义投影参数 + 内部拿到尺寸"的形态 |
| B. 强制外部传入投影实例 | 构造时必传 `SceneProjection` | ❌ Screen 层拿不到画布尺寸（circuit 现在正是用 `_canvasSize` hack 反向偷尺寸，circuit_screen.dart:53/:800——本需求要消灭的就是它）；调用方还得自己包 LayoutBuilder，把复杂度外推 |
| C. onItemDropped 改传屏幕坐标 | 调用方自行转换 | ❌ 破坏"回调里拿到的永远是 world 坐标"的既有契约（[来源: docs/knowledge/kratos/frontend/drag-drop-workspace.md:69]），把投影换算负担推给每个 sim，optics 这类本来正确的实现反而要加代码 |

### 3.2 根治原理（为什么 workaround 可以整体删除）

现状 circuit 的坐标链（两套投影混用）：

```
DropCanvas 内部: proj_A = CanvasProjection(sz, scale=1)         // origin=(w/2, h*0.55), 无 zoom
  → onItemDropped(type, proj_A.toWorld(local))                  // world_A 坐标（错误坐标系下的"世界"值）
_onComponentDrop（circuit_screen.dart:172-186 workaround）:
  screenLocal = proj_A.toScreen(world_A)                        // 逆变换回屏幕
  proj_B = SceneProjection(scale:1, origin:(w/2, h/2), zoom:_state.zoom)  // 渲染/hitTest 真实用投影
  worldPos = proj_B.toWorld(screenLocal)                        // 再正向变换
```

迁移后（工厂注入，**单一投影实例贯穿**）：

```
DropCanvas 内部: proj = projectionFactory(sz)                   // circuit 传入: origin=(w/2,h/2), zoom=_state.zoom
  → canvasBuilder(ctx, proj, sz) → _buildCanvas 直接消费 proj    // 渲染用同一实例
  → onItemDropped(type, proj.toWorld(local))                    // 落点与渲染同源
_onComponentDrop: 直接 _addComponent(type, worldPos)             // workaround（:172-186）+_canvasSize（:53/:800）整体删除
```

zoom 正确性：工厂闭包捕获 `_state.zoom`，zoom 变化触发 setState → DropCanvas 重建 → LayoutBuilder 重跑 → 工厂产出新 zoom 的投影 → canvasBuilder 拿到新实例。与现状 `_buildCanvas` 每帧自建投影（circuit_screen.dart:908-912）的更新时机**完全一致**。拖放 accept 闭包捕获的是 build 时刻的 proj 实例（drag_drop_workspace.dart:136 模式不变），拖放过程中 zoom 不会变（单指拖放与双指缩放互斥），行为等价。

### 3.3 对公共 API 的影响面与向后兼容

| API | 变更 | 兼容性 |
|-----|------|--------|
| `DropCanvas.canvasBuilder` | 签名 `Widget Function(BuildContext, CanvasProjection)` → `Widget Function(BuildContext, SceneProjection, Size canvasSize)`（新增第三参数，替代 `projection.canvasSize` 的消费场景，optics_screen.dart:545-546） | **破坏性变更**，但全仓使用者仅 circuit/optics 两处 lambda，MT-3 原子改造（F3）；integration_test 只用 `w is DropCanvas` 类型判定（app_test.dart:33/:166），不受影响 |

## 4. 公开 API 定义（签名级伪代码）

### 4.1 `lib/common/geometry/projection.dart`（新增）

```dart
import 'dart:ui';

/// 统一画布投影：world ↔ screen 仿射变换（screen = world × scale × zoom + origin）。
///
/// 合并自 CanvasProjection（drag_drop_workspace.dart · optics 系 · origin 固定 0.55H）
/// 与 SceneProjection（circuit 两处重复定义 · origin 注入 + zoom）。
/// 消费模式见 DropCanvas.projectionFactory（drag_drop_workspace.dart）。
class SceneProjection {
  const SceneProjection({
    required this.origin,
    this.scale = 1.0,
    this.zoom = 1.0,
  });

  /// world 原点在屏幕上的位置（如 optics: (w/2, h*0.55) 光轴；circuit: (w/2, h/2) 中心）
  final Offset origin;

  /// 世界单位 → 屏幕像素的基础换算（optics: 20；circuit: 1）
  final double scale;

  /// 用户交互缩放（circuit 0.6~2.0；默认 1.0 = 无缩放）
  final double zoom;

  /// 有效比例（scale × zoom）
  double get effectiveScale => scale * zoom;

  Offset toScreen(Offset world) =>
      Offset(world.dx * scale * zoom + origin.dx,
             world.dy * scale * zoom + origin.dy);

  Offset toWorld(Offset screen) =>
      Offset((screen.dx - origin.dx) / (scale * zoom),
             (screen.dy - origin.dy) / (scale * zoom));

  double toScreenLength(double world) => world * scale * zoom;
}
```

> 不加 `canvasSize` 字段（§1.2 决策）、不加 scale==0 防护（现状两实现均无，最小变更）。

### 4.2 `lib/common/geometry/hit_test.dart`（新增）

```dart
import 'dart:ui';

/// 点 p 到线段 ab 的最短距离（像素）。
/// 数学等价自 circuit_screen.dart:1071-1077 内联实现与
/// circuit_canvas.dart:167-179 `_pointToSegmentDistance`（两版逐位等价）。
/// a、b 重合时退化为 p 到 a 的距离。
double pointToSegmentDistance(Offset p, Offset a, Offset b) {
  final ab = b - a;
  final ap = p - a;
  final abLenSq = ab.distanceSquared;
  if (abLenSq == 0) return ap.distance;
  final t = (ap.dx * ab.dx + ap.dy * ab.dy) / abLenSq;
  final projection = a + ab * t.clamp(0.0, 1.0);
  return (p - projection).distance;
}
```

### 4.3 `lib/common/widgets/drag_drop_workspace.dart`（改造）

```dart
// 删除: class CanvasProjection（:16-22 整体删除）

class DropCanvas<T extends Object> extends StatelessWidget {

    super.key,
    required this.canvasBuilder,
    required this.onItemDropped,

  final double scale;

      },
      ... // 其余不变

  });
}
```
