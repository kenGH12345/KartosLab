# 需求简述 — 投影层统一技术债

> req-id: `req-unify-projection-layer` | SOP: agile-vibe | 创建: 2026-08-24

---

## 1. 背景与问题陈述

本项目（kratos 教育仿真）的画布坐标投影系统当前存在**两套平行实现、不共享基类**的结构性问题：

### 问题 A：两套投影类平行实现，不共享基类

| 投影类 | 位置 | origin 策略 | zoom 支持 | 使用者 |
|--------|------|-------------|-----------|--------|
| `CanvasProjection` | `lib/common/widgets/drag_drop_workspace.dart:16-22` | 固定 `(w/2, h*0.55)` | ❌ 无 | optics、DragDropWorkspace 通用拖放 |
| `SceneProjection` | `lib/circuit/widgets/circuit_canvas.dart:5-9` + `lib/circuit/screens/circuit_screen.dart:1156-1172`（**重复定义两处**） | 调用方传入 | ✅ 有 | circuit 渲染 + hitTest |

两者**不共享基类、不互相感知**（S1, S2, S6, S7, S8），导致公共拖放基础设施（`DragDropWorkspace`）产出的 world 坐标与 sim 内部渲染/命中检测坐标不一致。

### 问题 B：混用两套投影导致拖放错位 + 点选不中

电路屏的拖放路径经过 `DragDropWorkspace._DropCanvas`（使用 `CanvasProjection`），而渲染和命中检测使用 `SceneProjection`——**两套 origin 不同 (h*0.55 vs h/2) + zoom 语义缺失**，导致：
- 拖放元件后渲染位置偏移
- 点击无法选中元件

当前以 `_onComponentDrop` 中的**坐标来回转换 workaround** 掩盖此 bug（`circuit_screen.dart:172-186`）（S3, S9）。

> 通用教训：涉及投影/命中坐标换算时，缩放系数必须从组件内部状态读取，不可用默认值硬编码（S3）。

### 问题 C：命中检测位置统一但实现不在公共层

- 公共层仅有 `PositionElement.hitTest`（矩形命中检测，`lib/common/elements/position_element.dart:37`）（S10）
- 导线命中检测 `_hitTestWire` 存在**两份平行实现**：
  - `lib/circuit/widgets/circuit_canvas.dart:135`（S11）
  - `lib/circuit/screens/circuit_screen.dart:1057`（S12）
- 知识库明确记录：命中检测在 Screen 层用世界坐标，不在 Painter 内（S4）——但当前 Screen 层内部也是分散重复的

---

## 2. 目标

1. **统一投影抽象**：将两套投影类合并为一个共享基类/通用实现，放置到公共层（`lib/common/`），支持 origin 参数化 + zoom 可选（S1, S6, S7）
2. **消除混用 workaround**：移除 `_onComponentDrop` 中的坐标来回转换 hack，使拖放路径与渲染/hitTest 使用**同一投影实例**（S3, S9）
3. **命中检测上抽公共层**：将导线命中检测（线段距离判定）抽为公共能力，消除两份平行实现（S11, S12）

---

## 3. 非目标（明确不做）

| 不做的事 | 原因 |
|----------|------|
| 性能优化（如缓存投影计算） | 当前无性能瓶颈证据 |
| 修改渲染算法本身（Painter 绘制逻辑） | 不在本次重构范围 |
| 改变现有 sim 的视觉/交互行为 | **硬约束**：重构前后 circuit/optics 的拖放、点选、缩放行为必须完全一致（S13） |
| 新增 sim 接入 | 本需求只统一基础设施，不做新 sim 接线 |
| 修改 `PositionElement.hitTest` 矩形命中逻辑 | 已在公共层且工作正常 |

## 4. 验收标准（AC）

### AC-1：投影类统一且位于公共层

- [ ] 存在**唯一**公共投影类/基类（如 `Projection`）位于 `lib/common/`，支持：
  - `origin` 参数化（调用方传入，非硬编码）
  - `zoom` 可选参数（默认 1.0）
  - `toScreen(Offset world) → Offset screen`
  - `toWorld(Offset screen) → Offset world`
- [ ] `CanvasProjection`（`drag_drop_workspace.dart`）和 `SceneProjection`（circuit 两处）均**已删除或改为公共类的别名/子类**，不再存在平行独立定义
- [ ] 新公共组件已登记到 `docs/knowledge/kratos-java-simulations/shared-abstraction-plan.md` 候选表（S5）

**验证方式**：`grep -r "class.*Projection" lib/` 只命中公共层定义（或子类继承自公共基类）

### AC-2：circuit 拖放落点回归

- [ ] circuit 屏拖放元件后，元件渲染位置与拖放落点一致（无偏移）
- [ ] `_onComponentDrop` 中的 CanvasProjection→SceneProjection 来回转换 workaround（`circuit_screen.dart:172-186`）已移除
- [ ] 拖放后元件可正常点选命中

**验证方式**：flutter test 覆盖 circuit 拖放 + 点选场景；手动在 zoom=0.6/1.0/2.0 三档验证拖放准确性

### AC-3：optics 光轴行为保持

- [ ] optics 屏的光轴仍在画布高度 55% 位置（origin.dy = h * 0.55 语义保留）
- [ ] optics 元件拖放、点选行为无退化

**验证方式**：optics 相关 flutter test 全绿；手动验证光轴视觉位置未变

### AC-4：zoom 语义保留

- [ ] 统一投影类保留 zoom 参数化能力
- [ ] circuit 的 zoom 范围（0.6~2.0）行为不变：缩放后拖放、点选、渲染三者坐标一致

**验证方式**：circuit zoom 相关测试全绿；手动验证缩放极值下拖放/点选无偏

### AC-5：_hitTestWire 平行实现收敛

- [ ] `_hitTestWire`（导线/线段距离命中检测）只有**一份实现**
- [ ] 该实现位于公共层或 circuit 模块内唯一位置（不再存在 `circuit_canvas.dart` + `circuit_screen.dart` 两份平行代码）
- [ ] 命中检测行为不变（阈值 15px、线段逐段计算最短距离）

**验证方式**：`grep -r "_hitTestWire\|hitTestWire" lib/` 仅命中一处定义

### AC-6：flutter analyze 无新增 issue

- [ ] `flutter analyze` 零新增 error/warning（可有 info 级别历史遗留）

**验证方式**：`flutter analyze` 对比重构前后 issue 数量

### AC-7：flutter test 回归

- [ ] 项目现有 test 全部通过（允许重构前已失败的基线 case 不变，如 forces 超时）
- [ ] 无新增失败

**验证方式**：`flutter test` 全量运行

## 7. 风险与回滚策略

| 风险 | 概率 | 影响 | 缓解/回滚 |
|------|------|------|-----------|
| 统一投影类接口设计不当，导致某 sim 的特殊需求无法表达 | 低 | 高 | 技术方案阶段充分对比两套投影的公式差异；回滚：git revert 整个重构 commit |
| 移除 workaround 后引入新的坐标偏移 bug | 中 | 高 | AC-2/AC-3/AC-4 覆盖；回滚：恢复 workaround 代码段 |
| hitTestWire 上抽后签名变化导致调用方编译不过 | 低 | 低 | flutter analyze 门禁拦截 |
| optics 0.55 参数化后视觉微偏 | 低 | 中 | 对比重构前后 optics 截图；回滚：参数值微调 |
