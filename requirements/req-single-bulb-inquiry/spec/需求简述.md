# 需求简述 · 色觉单光源屏接入做中学探究抽屉

> **需求 ID**：req-single-bulb-inquiry
> **版本**：v1.0（2026-08-18）
> **SOP**：agile-vibe
> **来源**：PRD v2.1 审核差异 D3（S1）
> **优先级**：P1（PRD 声明失真 · 功能缺失）

## 1. 背景与目标

### 1.1 问题陈述

PRD §5.5.3 声称色觉模块「探究工作流 P0 已接入做中学流程」，但实际情况是：

- **rgb_bulbs_screen**（RGB 三色加色屏）→ **已接入** InquiryDrawer（S3）
- **single_bulb_screen**（单光源滤光片屏）→ **未接入**，仅有 ExperimentIntroPanel 常驻引导，无探究抽屉（S2）

此外，色觉场景目录中现有 3 个 `singleBulb` 场景（S4）均为纯观察型，不含 `inquiryTask` 字段，无法驱动探究工作流。

### 1.2 目标

让 single_bulb 屏接入与 rgb_bulbs 屏一致的做中学探究工作流，具体包括：

1. **InquiryDrawer 接入**：复用 L0 通用组件（inquiry_drawer / experiment_logger / conclusion_panel / snapshot_chart / prediction_panel），禁止平行实现（S12）
2. **新增探究场景 JSON**：至少 1 个 `screen: "singleBulb"` 的场景配置含 `inquiryTask`（含 question/steps/referenceConclusion/snapshotColumns）
3. **PRD 声明如实**：修复完成后 PRD §5.5.3 描述不再失真

### 1.3 用户故事

> 作为一个使用色觉模块的学生，当我进入单光源滤光片屏（有探究场景时），我希望看到做中学探究抽屉（任务指引→记录实验→归纳结论），以便我能在动手操作后主动总结滤光原理，而非被动观察。

## 2. 功能范围

### F1：InquiryDrawer 接入 single_bulb_screen

**描述**：在 `single_bulb_screen.dart` 中引入 `InquiryDrawer`（L0 组件），传入标准四参数（`task` / `columns` / `snapshotProvider` / `open`）。

**验收标准 AC-1**：
- 当加载的场景含 `inquiryTask` 时，InquiryDrawer 默认展开（与 PRD §10.2 统一策略一致：`_inquiryOpen = scenario.inquiryTask != null`）（S6）
- 当场景不含 `inquiryTask` 时，抽屉与入口按钮自动隐藏，无副作用（S6）
- InquiryDrawer 内包含：进度条 + InquiryTaskPanel + ExperimentLogger + SnapshotChart + ConclusionPanel（与 rgb_bulbs_screen 一致）（S3）
- 复用 `lib/common/widgets/inquiry_drawer.dart`，**禁止新建平行抽屉实现**（S12）

**验收标准 AC-2**（入口按钮）：
- 有 `inquiryTask` 的场景在 NineGridLayout 某边格显示探究入口按钮（IconButton，图标 `Icons.science_outlined`），点击切换 `_inquiryOpen`
- 按钮位置：topRight（首选）或 bottomLeft（视 NineGridLayout 已有占位情况，由 tech-leader 定具体位置）（S5）

### F2：snapshotProvider 实现

**描述**：提供 `Map<String, dynamic> _singleBulbSnapshot()` 函数，返回当前实验参数与读数的快照。

**记录列设计（建议方案 — 已确认）**：

| key | label | source | 取值说明 |
|-----|-------|--------|---------|
| `bulbMode` | 光源 | param | 白光 / 单色光 |
| `wavelength` | 波长(nm) | param | 仅 mono 模式有效；white 时可记 "—" 或白光默认值 |
| `filter` | 滤光片 | param | none / red / green / blue / custom |
| `perceivedColor` | 看到颜色 | reading | 经滤光后人眼感知颜色名称 |

**验收标准 AC-3**：
- snapshotProvider 返回的 key 与探究场景 JSON 中 `snapshotColumns[].key` **逐项一致**（S5 §AC④ 先例）
- ExperimentLogger 点击「记录本次实验」后，记录表新增一行数据正确反映当前 sim 状态
- SnapshotChart 渲染正常（x=第一个 param 列，y=第一个 reading 列；或按 snapshotColumns 定义）

### F3：探究场景 JSON（至少 1 个）

**描述**：新增至少 1 个 `screen: "singleBulb"` 的场景 JSON 文件，放置于 `assets/scenarios/color-vision/`，含完整 `inquiryTask`。

**探究场景设计建议（PM 推荐方案）**：

场景名称：**"滤光片减色探究"**（`single-inquiry-subtractive`）

| 字段 | 建议内容 |
|------|---------|
| question | "白光通过不同颜色的滤光片后，人眼看到什么颜色？你能总结出减色法规律吗？" |
| steps | 3 步：①选白光+红色滤光片→记录；②换绿色/蓝色滤光片各记录；③回顾规律 |
| referenceConclusion | "减色法：白光含 R+G+B，红色滤光片只透红，绿色只透绿，蓝色只透蓝。滤光片的颜色决定了透过的光——这就是舞台灯光的原理。" |
| snapshotColumns | 同 F2 表格 |

**验收标准 AC-4**：
- 场景 JSON 满足 `ColorVisionScenario` 模型的 fromJson 解析（含 `screen: "singleBulb"` + `inquiryTask` 完整字段）
- 至少包含 2 个 steps（分步指引）
- 包含 `referenceConclusion`（结论面板对照用）
- 包含 `snapshotColumns`（≥ 2 列，至少 1 个 param + 1 个 reading）
- manifest.json 中注册该新场景

### F4：进度条节点数

**描述**：根据 PRD §10.3（S11），进度条节点数由数据自动决定：

- 有 `predictions` → 3 节点（猜测 → 记录 → 归纳）
- 无 `predictions` → 2 节点（记录 → 归纳）

**PM 建议**：本次 single_bulb 探究场景 **不含 predictions**（预测题功能当前仅在 circuit/molarity 试点，PRD §10.7 明确为后续扩展）。因此进度条应为 2 节点。

**验收标准 AC-5**：
- 加载本需求新增场景时，InquiryDrawer 进度条显示 2 节点（记录 → 归纳）
- 若未来场景 JSON 增加 `predictions` 字段，进度条应自动升为 3 节点（已由 L0 组件保证，无需额外开发）

### F5：NineGridLayout 布局合规

**验收标准 AC-6**：
- InquiryDrawer 叠加后，中间格主图面积仍 ≥ 70%（抽屉 Offstage 不挤占中间格空间，浮于上方）（S12 L0-1）
- 视口宽度 320-1920px × 高度 480-1080px 全区间内无 overflow 红黑报错（S12 L0-2）
- 抽屉关闭再打开后，ExperimentLogger 记录和 ConclusionPanel 状态**不丢失**（Offstage 保持 State）（S6）
- `flutter analyze lib/color_vision/` 无新增 error/warning

## 5. 与 req-color-vision-layout-fix 的冲突规避

### 5.1 冲突风险分析

两需求改动同一文件 `single_bulb_screen.dart`：

- **req-color-vision-layout-fix**（S7）：修复窄视口布局崩溃，改动 build 方法中的 Column/Flex 布局结构
- **本需求**：在 NineGridLayout 外层叠加 InquiryDrawer（Stack 包裹），新增 snapshotProvider 方法和 _inquiryOpen 状态

### 5.2 规避策略

| 策略 | 描述 |
|------|------|
| **顺序约束** | 建议 req-color-vision-layout-fix 先完成合入（phase 3.iteration 较本需求进度更前），本需求基于修复后的文件状态开发 |
| **改动隔离** | 本需求改动（InquiryDrawer 叠加 + 入口按钮 + snapshot 方法）与布局修复改动（Column flex/scroll 结构）**正交**——布局修复改内部结构，InquiryDrawer 在外层 Stack 叠加 |
| **回归验证** | 本需求 AC-6 已要求"无 overflow"，可覆盖布局修复的回归场景 |
