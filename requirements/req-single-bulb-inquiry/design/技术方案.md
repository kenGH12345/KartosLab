### T1 · ColorVisionScenario 对 singleBulb 场景的 inquiryTask 解析 —— ✅ 已支持，无需改 model

**结论**：`ColorVisionScenario.fromJson` 解析 `inquiryTask` 时**不按 screen 类型分支**，`screen: "singleBulb"` 场景可直接携带 `inquiryTask`。

**代码证据**：
- `lib/color_vision/config/color_vision_scenario.dart:211-213` — `inquiryTask: json['inquiryTask'] != null ? InquiryTask.fromJson(...) : null`，与 `screen` 解析（line 197）完全独立，无任何 screen 条件判断。

### T2 · InquiryDrawer 接入方式 —— ✅ 需外包 Stack，照 rgb 实证模式

**结论**：rgb 屏是 `Stack(children: [NineGridLayout(...), InquiryDrawer(...)])` 结构；single_bulb 当前直接返回 NineGridLayout，**需在 build 外包一层 Stack**，InquiryDrawer 作为 Stack 第二子节点浮于九宫格上方。

**代码证据**：
- `lib/color_vision/screens/rgb_bulbs_screen.dart:311-375` — build 返回 Stack，第一子节点 NineGridLayout（line 313-363），第二子节点 InquiryDrawer（line 365-372，四参数：task/columns/snapshotProvider/open）。
- `lib/common/widgets/inquiry_drawer.dart:56-64` — 内部 `Offstage` + `Align(centerRight)` + 固定宽 280，浮于底层之上、不挤占九宫格空间（满足 AC-6 主图 ≥70%）。
- `lib/common/widgets/inquiry_drawer.dart:55` — `task == null` 时返回 `SizedBox.shrink()`，纯观察场景零渲染（回退安全性由组件内建保证）。
- `lib/color_vision/screens/single_bulb_screen.dart:136-160` — 当前 build 直接返回 NineGridLayout，占位情况：topCenter（ExperimentIntroPanel）/ center / footer / bottomRight（知识点）。**topRight / midLeft / bottomLeft 空闲**。

**入口按钮位置决策**：**topRight**（spec AC-2 首选 · 当前无占位）。样式照抄 rgb 已实证模式（`rgb_bulbs_screen.dart:377-389`：`Center` + `IconButton.filledTonal` + `VisualDensity.compact` + `Icons.science_outlined, size 20`）。备注：X3 排除了场景菜单，topRight 暂无竞争；若未来加场景菜单再迁移按钮位置（低成本）。

### T3 · req-color-vision-layout-fix 进展与本需求开发起点 —— ✅ 修复已生效于工作区，基于当前文件状态开发

**结论**：layout-fix 代码改动（方案 B · footer 横排）**已体现在当前工作区文件中**且 AI 侧测试全绿；本需求以当前 `single_bulb_screen.dart` 为开发起点，改动区域与其正交。

## 2. 关键新发现 · spec 未覆盖点（需用户拍板）

### D-1 · 滤光镜 Tab 场景 ID 硬编码 —— 新探究场景默认不可达

**事实**：`lib/color_vision/screens/color_vision_home.dart:37` —
```dart
final filterScenario = mgr.findById('single-white-red-filter');
```
SingleBulbScreen 的场景 ID 是**硬编码**的。即使新增 `single-inquiry-subtractive.json` 并注册 manifest（AC-4），滤光镜 Tab 仍加载纯观察场景，InquiryDrawer 永远不出现——新场景成为死资产，AC-1/AC-3/AC-5 无法通过应用内手动路径验证（rgb 屏靠 scenarioList 菜单切换，single_bulb 屏 X3 明确不做菜单）。

**推荐方案**（1 行改动，带防御性 fallback）：
```dart
final filterScenario = mgr.findById('single-inquiry-subtractive')
    ?? mgr.findById('single-white-red-filter');
```
- 默认场景切换为探究场景 → AC-1/3/5 端到端可达，PRD §5.5.3 声明不再失真（spec §1.2 目标 3）。
- fallback 保证场景文件缺失/解析失败时行为回退现状（不 crash · 向后兼容）。
- 代价：滤光镜 Tab 默认场景从"白光+红滤光片（纯观察）"变为"滤光片减色探究"。原 3 个纯观察场景本就只有 `single-white-red-filter` 被加载（另 2 个本就不可达），信息无损。

**需用户拍板**：是否接受默认场景切换？（替代方案：保持默认纯观察场景，新场景仅靠测试可达 → 不推荐，AC 手动验证路径断裂）

## 5. 风险与回退

### 5.1 无 inquiryTask 场景行为不变（回退安全性）

| 保护机制 | 证据 |
|---|---|
| `_inquiryOpen` 初始 false；`initState` 仅在 `inquiryTask != null` 时置 true | 模式同 `rgb_bulbs_screen.dart:58,72-73` |
| 入口按钮 `task == null` → `SizedBox.shrink()` | 模式同 `rgb_bulbs_screen.dart:379-380` |
| InquiryDrawer `task == null` → `SizedBox.shrink()`（组件内建） | `inquiry_drawer.dart:55` |
| build 外层 Stack 单子节点布局行为等价 | Stack 无定位子 = 铺满同尺寸 |

→ 现有 3 个纯观察 singleBulb 场景（无 inquiryTask）渲染结果与改动前**像素级一致**。

### 5.2 风险登记表
