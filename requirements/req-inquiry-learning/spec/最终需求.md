## 1. 原始需求

见 `spec/需求简述.md`（v1.0 · 2026-08-07）。

**核心诉求**：依据 ICAP 框架（Chi & Wylie 2014），将 7 个 sim 从 Active 层（看/按/拖拽）升级到 Constructive 层（做中学：通过实验找规律、自主得出结论）。

升级三要素：
1. **探究驱动**（替代演示驱动）：用开放问题引导实验方向（InquiryTaskPanel）
2. **数据留痕**（替代即看即忘）：学生可记录实验数据、多次对比（ExperimentLogger）
3. **自主建构**（替代结论灌输）：学生先归纳、再对照参考结论（ConclusionPanel，实现"结论先消失"）

**范围（用户确认 4 问）**：
- Q1 = 通用层 + 2 pilot sim（circuit + color_vision），验收后再推广其余 5 sim
- Q2 结论验证 = 学生自评 + 可对照标准结论
- Q3 数据记录 = 手动快照表
- Q4 挑战模式 = color_vision 硬编码挑战迁移到 JSON 驱动

**验收项**：23 项（AC-1.x=7 · AC-2.x=4 · AC-3.x=6 · AC-4.x=5 · AC-5.x=5）

- **布局方案（D6→D6'）**：技术方案原定 color_vision 三组件入 `midLeft` 边条。执行发现 midLeft 在窄视口仅 ~41px，放不下任务卡/记录表/结论面板。改为新增通用 `InquiryDrawer`：用 `Offstage` 常驻三组件（保持 ExperimentLogger 记录/ConclusionPanel 两阶段 State 不因抽屉开合丢失），右侧 280px 固定宽度抽屉，两 sim 在 midLeft 只放"探究入口按钮"。该抽屉组件亦进入 `lib/common/widgets/`（L1 候选登记）。
- **AC-4.4 测试（D9）**：原测试经 `manager.loadScenarios`（rootBundle 真实 IO）在 fake async 下挂起。改为**内联构造场景**绕开 IO，3/3 通过。
- **Blocker 修复**：code-reviewer 首轮发现 AC-4.4 触发链路断裂（`MagicLabScreen` 自行构造 state 不经过 manager → `_currentScenario` 恒 null → `checkObjectives` 恒 false）。修复：manager 加 `setCurrentScenario()` + `currentScenario` getter，`MagicLabScreen.initState/_applyScenario` 同步；并补 `rgb-challenge-basic.json` 缺失的 `successCriteria`。
- **Minor-2 修复**：`rgb_bulbs_screen.dart` initState 判空后再 `setCurrentScenario`（消除空安全 NPE 隐患）。
