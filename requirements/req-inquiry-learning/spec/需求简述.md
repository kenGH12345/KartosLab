# 从"可视化可操作"到"做中学" —— 探究工作流整体升级

> **spec 版本**：v1.0（2026-08-07）
> **需求 ID**：req-inquiry-learning
> **SOP**：agile-vibe
> **性质**：通用能力上抽 + 2 pilot sim 接入（非新sim 复刻）
> **优先级**：P1（交互层架构级升级）
> **来源归档**：`spec/context/来源归档.md`

---

## 1. 背景与动机

### 1.1 理论依据（S1）

ICAP 框架（Chi & Wylie 2014）将学习活动按认知投入分四层：

| 层级 | 学生行为 | 典型课堂表现 |
|------|---------|-------------|
| Passive（被动） | 接收 | 看教师操作演示 |
| Active（主动） | 操作/复述 | 拖拽参数观看变化 |
| **Constructive（建构）** | 自主生成新理解 | 通过实验数据归纳规律 |
| **Interactive（交互）** | 协同建构知识 | 分组讨论/互评 |

核心论断："**结论先消失，学生才有空间建构。**"

### 1.2 项目现状（S3）

本项目 7 个 sim（circuit / optics / forces / color_vision / sound / radio_waves / wave_interference）当前处于 **Active 层**：

-学生**可以**拖拽参数、看到仿真结果变化
- 但 **无从**"发现规律"——没有实验记录、没有归纳引导、没有探究任务驱动
- `knowledge_panel` 是**灌输型**知识展示，结论预先给出（违背"结论先消失"原则）
- scenario JSON 已定义 objectives/hints/successCriteria，但 7 sim **无一**在 screen 层调用验证逻辑——**数据层已就绪，交互层零消费**

### 1.3 升级目标（S1, S2）

**从 Active 层升级到 Constructive 层**：让学生"通过实验找规律、自主得出结论"。

升级三要素：
1. **探究驱动**（替代演示驱动）：用开放问题引导实验方向
2. **数据留痕**（替代即看即忘）：学生可记录实验数据、多次对比
3. **自主建构**（替代结论灌输）：学生先归纳、再对照参考结论

## 2. 三层探究工作流设计（通用能力 · 进`lib/common/`）

### 2.1 总览

```
┌─────────────────────────────────────────────────┐
│  探究任务卡 (InquiryTaskPanel)                    │
│  "改变电阻值，观察灯泡亮度变化，找出规律"            │
└─────────────────────┬───────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────┐
│  学生操作 sim + 实验记录器 (ExperimentLogger)      │
│  [记录本次实验] →表格追加一行: {参数, 读数, 备注}  │
└─────────────────────┬───────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────┐
│  结论归纳 (ConclusionPanel)                       │
│  学生输入自己的规律 → 提交 → 可展开"参考结论"对照│
└─────────────────────────────────────────────────┘
```

### 2.2 探究任务卡（InquiryTaskPanel）

**职责**：展示当前 scenario 的探究问题，引导学生实验方向

| 属性 | 说明 |
|------|------|
| 数据来源 | scenario JSON `inquiryTask.question` 字段 |
| UI 形态 | 卡片样式，标题 + 开放问题 + 可选实验指引 |
| 交互 | 只读展示，可折叠/展开 |
| 位置 | 九宫格 topCenter 或 topLeft（由各 sim 决定） |

**行为规则**：
- 若当前 scenario JSON 无 `inquiryTask` 字段 → **不显示**（向后兼容）（S4-Q1, S7）
- 支持多步骤探究（`inquiryTask.steps[]`）：按序展示，完成一步解锁下一步

### 2.3 实验记录器（ExperimentLogger）

**职责**：让学生手动快照当前实验状态，积累对比数据（S4-Q3）

| 属性 | 说明 |
|------|------|
| 触发 | 学生点击"记录本次实验"按钮 |
| 记录内容 | 各sim 提供的 `snapshotProvider` 回调返回当前参数 + 读数 Map |
| 展示 | 表格形式，每行 = 一次快照（序号、时间戳、各参数值、各读数值） |
| 操作 | 清空全部记录 / 删除单行 / [待技术确认: 导出格式（CSV?截图?）] |
| 容量 | 单scenario最多 20 条记录（超出提示清空最早的） |
| 位置 | 九宫格 bottomCenter 或作为可展开侧面板（由各 sim 决定） |

**通用接口设计**：
- `ExperimentLogger` widget接收一个 `List<ColumnDef>` 定义表头 + 一个 `SnapshotProvider` 回调
- 各 sim 只需实现 `SnapshotProvider`（返回 `Map<String, dynamic>`），通用组件负责表格渲染和数据管理
- 数据仅在内存中（session 级），不持久化到本地存储 [基于假设: 教学场景为课堂即时使用，无需跨 session 保存]

### 2.4 结论归纳（ConclusionPanel）

**职责**：引导学生从实验数据中自主归纳规律，再对照参考结论（S1, S4-Q2）

| 属性 | 说明 |
|------|------|
| UI 形态 | 分两阶段：① 输入区（文本框+ 提交按钮） ② 对照区（参考结论 + 学生结论并排） |
| 流程 | 学生写出规律 → 点"提交我的结论" → 参考结论**才**展开可见 |
| 数据来源 | scenario JSON `inquiryTask.referenceConclusion` 字段 |
| 限制 | 提交前参考结论**不可见**（实现"结论先消失"） |
| 位置 |紧邻实验记录器下方，或作为独立底部面板 |

**行为规则**：
- 学生可多次修改自己的结论（提交后仍可编辑再次提交）
- 参考结论一旦展开不可收回（防止"看完答案假装没看"）
- 若scenario JSON 无 `referenceConclusion` →隐藏对照功能，仅保留自由输入

## 3. Scenario JSON Schema 扩展

### 3.1 新增 `inquiryTask`顶层字段（S7, S8）

```jsonc
{
  "scenarioId": "...",
  "name": "...",
  // ... 现有字段保持不变 ...

  //🆕 探究任务（可选字段 ·缺失时不启用探究模式）
  "inquiryTask": {
    "question": "改变电阻值，观察电流和灯泡亮度的变化，你能发现什么规律？",
    "steps": [
      {
        "id": "step-1",
        "instruction": "保持电压不变（10V），将电阻从 5Ω 逐步调到 50Ω，记录至少 5 组数据",
        "hint": "每次改变电阻后，等待 1秒让电路稳定再记录"
      },
      {
        "id": "step-2",
        "instruction": "观察你的数据表，电流和电阻之间有什么关系？"
      }
    ],
    "referenceConclusion": "电压不变时，电流与电阻成反比（I = V/R，即欧姆定律）",
    "snapshotColumns": [
      { "key": "resistance", "label": "电阻(Ω)", "source": "param" },
      { "key": "current", "label": "电流(A)", "source": "reading" },
      { "key": "brightness", "label": "灯泡亮度", "source": "reading" }
    ]
  }
}
```

### 3.2 字段说明

| 字段路径 | 类型 | 必须 | 说明 |
|---------|------|:----:|------|
| `inquiryTask` | Object | 否 | 整个探究任务块；缺失时 sim 以传统模式运行 |
| `inquiryTask.question` | String | 是* | 核心探究问题（*若inquiryTask 存在则必须） |
| `inquiryTask.steps` | Array | 否 | 分步实验指引；缺失时只展示 question |
| `inquiryTask.steps[].id` | String | 是 | 步骤唯一标识 |
| `inquiryTask.steps[].instruction` | String | 是 | 步骤指引文本 |
| `inquiryTask.steps[].hint` | String | 否 | 步骤提示（可选） |
| `inquiryTask.referenceConclusion` | String | 否 | 参考结论；缺失时不展示对照功能 |
| `inquiryTask.snapshotColumns` | Array | 否 | 实验记录表列定义；缺失时由 sim 代码默认提供 |
| `inquiryTask.snapshotColumns[].key` | String | 是 | 对应snapshotProvider 返回 Map的 key |
| `inquiryTask.snapshotColumns[].label` | String | 是 | 表头显示文字 |
| `inquiryTask.snapshotColumns[].source` | Enum | 是 | `"param"` = 学生设的参数；`"reading"` = 仿真产出的读数 |

### 3.3 向后兼容策略（S7, S8）

- `inquiryTask` 为**可选**顶层字段
- 现有所有 scenario JSON（7 sim 共10+ 文件）**无需修改**即可正常运行
- 通用组件在读取 scenario时：`if (json['inquiryTask'] != null)` 才初始化探究 UI
- ScenarioManagerBase 解析时忽略未知字段（现有实现已如此）（S9）

### 3.4 挑战模式 JSON 扩展（color_vision 专用）（S4-Q4, S10）

```jsonc
{
  "scenarioId": "rgb-challenge-basic",
  "name": "颜色匹配挑战 · 初级",
  "screen": "rgb",
  // ... 现有字段 ...

  // 🆕 挑战模式配置（替代硬编码）
  "challenge": {
    "enabled": true,
    "mode": "colorMatch",
    "difficulty": "easy",
    "timeLimit": 30,
    "timeBonusPerLevel": 5,
    "accuracyThreshold": 95.0,
    "targets": [
      { "color": "#FFFF00", "label": "黄色（红+绿）" },
      { "color": "#FF00FF", "label": "品红（红+蓝）" },
      { "color": "#00FFFF", "label": "青色（绿+蓝）" }
    ],
    "randomTargets": {
      "enabled": true,
      "count": 5,
      "excludeGrayscale": true
    }
  }
}
```

| 字段路径 | 类型 | 说明 |
|---------|------|------|
| `challenge` | Object | 挑战模式配置块；缺失时无挑战模式 |
| `challenge.enabled` | Boolean | 是否启用 |
| `challenge.mode` | Enum | 挑战类型（当前仅 `colorMatch`，预留扩展） |
| `challenge.difficulty` | Enum | `easy/medium/hard`（影响 UI 提示丰富度） |
| `challenge.timeLimit` | Number | 基础倒计时秒数 |
| `challenge.timeBonusPerLevel` | Number | 每过一关额外增加的秒数 |
| `challenge.accuracyThreshold` | Number | 匹配精度阈值（0-100），替代硬编码 99.99% |
| `challenge.targets` | Array | 预设目标色列表（按序出题） |
| `challenge.randomTargets` | Object | 随机目标色配置（用完targets 后或直接使用） |

## 4. 挑战模式 JSON 驱动化（color_vision）

### 4.1 现状问题（S3, S10）

`rgb_bulbs_screen.dart` 硬编码：
- `_randomColor()` 纯随机 RGB（可能产生灰/黑等无意义色）
- 倒计时 `30+ (level-1)*5`硬编码
- 精度阈值 99.99% 硬编码（过于严苛）
- 与 scenario JSON 的 `successCriteria` 完全脱钩

### 4.2 目标改造

| 改造点 | 现状 | 目标 |
|--------|------|------|
| 目标色来源 | `_randomColor()` 硬编码 | JSON `challenge.targets` + `randomTargets` |
| 倒计时 | `30 + (level-1)*5` 硬编码 | JSON `challenge.timeLimit` + `timeBonusPerLevel` |
| 精度阈值 | `99.99%` 硬编码 | JSON `challenge.accuracyThreshold` |
| 难度反馈 | 无 | 根据 `difficulty` 决定是否显示 RGB 数值提示 |
| successCriteria 统一 | 脱钩 | 挑战完成写入 objectives体系，复用 `checkObjectives` |

### 4.3 行为变更

- 启动挑战时：读取 `challenge.targets`，按序出题；用完后若有 `randomTargets` 配置则随机生成
- 匹配判定：使用 `challenge.accuracyThreshold`（默认 95.0）替代硬编码 99.99%
- 倒计时：`challenge.timeLimit + passedLevels * challenge.timeBonusPerLevel`
- 挑战完成：触发 `checkObjectives` 标记 scenario 目标达成（与 successCriteria 统一）
- **向后兼容**：若 scenario JSON 无 `challenge` 字段，现有硬编码逻辑作为 fallback 保留（不删除，仅标记 deprecated）

## 5. 2Pilot Sim 接入点

### 5.1 Circuit（电路）

**选择理由**：已有最丰富的 scenario JSON 结构（8 个 scenario文件），且欧姆定律是经典探究实验场景。

| 接入点 | 说明 |
|--------|------|
| InquiryTaskPanel | 九宫格 topCenter 展示探究问题（如"改变电阻观察电流"） |
| ExperimentLogger | 九宫格 bottomCenter，snapshotProvider 读取当前电路的电压/电流/电阻/灯泡亮度 |
| ConclusionPanel | 在 ExperimentLogger 下方或作为 tab 切换展示 |
| Scenario 数据 | 为 `simple-series.json` 补充 `inquiryTask` 字段（探究欧姆定律） |
| objectives消费 | 调用 `checkObjectives` 验证学生是否完成了探究步骤 |

**交互流程**：
1. 学生选择"简单串联电路"scenario → 看到探究任务卡："保持电压不变，改变电阻，观察电流变化规律"
2. 学生按指引操作：调电阻滑块→ 观察电流表读数 → 点"记录本次实验"
3. 重复 5+ 次后，查看实验记录表对比数据
4. 在结论面板输入发现的规律 → 提交 → 展开参考结论对照

### 5.2 Color Vision（颜色视觉）

**选择理由**：已有挑战模式需迁移 JSON 驱动；RGB 混色规律适合探究式学习。

| 接入点 | 说明 |
|--------|------|
| InquiryTaskPanel | 九宫格 topCenter 展示探究问题（如"红+绿=？试试看"） |
| ExperimentLogger | 九宫格 bottomCenter，snapshotProvider 读取 R/G/B 滑块值 + 混合色结果 |
| ConclusionPanel | 学生归纳加色混合规律 |
| 挑战模式 JSON 驱动 | `rgb-default.json` 补充 `challenge` 字段；新增 `rgb-challenge-basic.json` |
| Scenario 数据 | 新增探究型 scenario（如 `rgb-inquiry-additive.json`） |

**交互流程**：
1. **探究模式**：学生选择"加色混合探究" scenario → 看到任务"分别组合两种光，记录混合结果，找出规律"→ 操作 R/G/B 滑块 → 记录 → 归纳"R+G=黄, R+B=品红, G+B=青"
2. **挑战模式**（升级后）：从 JSON 读取目标色/倒计时/精度 → 学生调色匹配 → 达到阈值触发成功 → 与objectives 统一
