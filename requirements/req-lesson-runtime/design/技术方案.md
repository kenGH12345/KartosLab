## 0. 方案总览与两项技术待确认结论

### 0.1 两项 PM 交接技术待确认项的解决

**待确认 1 · 试点剧本场景选择**（读两 sim manifest 实际场景清单 + 判定链现状后定）：

| 剧本 | 节点场景序列 | 选择依据 |
|---|---|---|
| circuit 线性（P1）「开关与电路诊断」 | controlled-switch → open-circuit-debug → fuse-blown → 终点 | controlled-switch 开关初始断开（`controlled-switch.json:89` `"isClosed": false`）学生合闸才满足 circuitClosed；open-circuit-debug 回路缺导线（manifest 描述"学生补齐最后一根导线"）需补线；fuse-blown 初始闭合秒完成已坐实（§9 R2 · 评审实证：全模块无熔断逻辑 `circuit_solver.dart:242-243` + isClosed 默认 true `circuit_scenario.dart:137,158`）→ 按预案①定稿为**观察型节点**（description 改观察引导） |
| circuit 条件（P2）「欧姆定律与电路诊断」 | simple-series → routes 分流（open-circuit-debug 挑战线 / controlled-switch 复习线）→ 汇合 fuse-blown → 终点 | simple-series 是 circuit 唯一带 `predictions` 的场景（`simple-series.json:138-153` 2 道预测题，全项目仅 simple-series + molarity/default 有预测题——grep 实证）；探究工作流"预测全验证→任务解锁→操作解锁"阶段门禁（`shared-abstraction-plan.md` 候选 8）天然保证先预测后操作，routes 求值时 predictionScore 有真实数据 |
| color_vision 线性（P1）「RGB 加色法」 | rgb-yellow-only → rgb-cyan-challenge → rgb-challenge-basic → 终点 | 三场景均为 rgb 屏 + successCriteria 全部 `colorMatch` 类型（`rgb-yellow-only.json:13-16`、`rgb-cyan-challenge.json:13-16`、`rgb-challenge-basic.json:27-29`）——CVCriterionConfig 仅实现 colorMatch 求值（守卫测试豁免表：'部分实现：evaluateLeaf 1/3（colorMatch）'，`scenario_runtime_wiring_test.dart:38`），需操作达成（初始 R=G=B=0 或单色，不满足目标色） |
| color_vision 条件（P2）「色彩挑战之路」 | rgb-yellow-only → rgb-cyan-challenge（unlock: all[nodeCompleted n1]）→ rgb-challenge-basic（unlock: any[nodeCompleted n1, n2]）→ 终点 | color_vision 无 predictions 场景 → predictionScore 无数据源（fail-safe 恒 false 走兜底，AC-33 语义正确但无教学分流价值）；本剧本以 unlock 门禁 + all/any 组合树为主要展示（AC-44），routes 分流语义由 circuit 条件剧本承载（AC-43/45） |
| **跨 sim 混合（P1）「电与光的探索」**（v1.1 新增 · AC-58） | circuit/controlled-switch → color_vision/rgb-yellow-only → circuit/open-circuit-debug → 终点 | Blocker-2 修法 B（用户拍板）：把「跨 sim 天然支持」从设计声明转为**验收实证**——节点序列 circuit→cv→circuit 双向穿越，`dispatch()` 分派（D9）与同课时异 sim 宿主切换被端到端验证；三场景均为已验证可完成场景（两 sim 完成信号钩子均已接线） |

**关键排除证据**（为何不用某些场景做"完成驱动"节点）：
- `simple-series` / `parallel-bulbs` / `two-batteries` 初始布局即完整闭合回路（`simple-series.json:54-74` w1-w3 成环、`parallel-bulbs.json:109-139` w1-w6 成环）→ 加载后首次交互即满足 `circuitClosed + bulbBrightness` criteria → 节点"一操作即完成"，学生来不及做完整探究任务。仅 simple-series 因预测题数据源价值被条件剧本 n1 使用（其流转语义见 §9 风险 R1 缓解）。
- `rgb-dark-room` 的 criteria 含 `intensityReached`（`rgb-dark-room.json:14`，CVCriterionConfig 未实现该求值 → 恒 false）→ 不可用作完成驱动节点。**v1.1 起由 scenarioPlayable 解析期强制拦截（D10）**。
- `rgb-inquiry-additive` 无 successCriteria（grep 实证仅有 inquiryTask）→ 无完成信号，不可用。**v1.1 起由 scenarioPlayable 解析期强制拦截（D10）**。
- color_vision 的 singleBulb 屏场景（single-white-red-filter 等 4 个）判定叶子 `filterPassed` 未实现（同 1/3 现状）且 SingleBulbScreen 无 `.checkObjectives(` 消费点 → **试点剧本一律不引用 singleBulb 屏场景**（v1.1 起由 scenarioPlayable 统一拦截，R5 并入 D10）。
- circuit 侧无 objectives 的场景（如 `default`，objectives null → checkObjectives 恒 true → 秒完成，评审 Major-4 实证 `circuit/config/scenario_manager.dart:114`）→ 不可用作完成驱动节点。**v1.1 起由 scenarioPlayable 解析期强制拦截（D10）**。

**待确认 2 · InquiryDrawer 转发接线**：

- **签名**：`final void Function(int verified, int correct)? onPredictionResult;` —— InquiryDrawer 构造函数新增可选命名参数，默认 null。
- **挂载点**：`_stageContent` 的 prediction 分支（`inquiry_drawer.dart:337-344`）——PredictionPanel 已有 `onResultChanged(verified, correct)` 回调且在 InquiryDrawer 内部消费（`inquiry_drawer.dart:340-343`），改造为在现有闭包内**追加**一行 `widget.onPredictionResult?.call(verified, correct);`，不改变现有消费逻辑。
- **向后兼容依据**：项目两处先例同模式——`prediction_panel.dart:31` `onResultChanged` 本身即可选参数（null 时 `_notify()` 内 `?.call` 短路，`prediction_panel.dart:64`）；`ExperimentLogger.onRowsChanged` 可选回调（shared-abstraction-plan.md 候选 8）。不传参数时 `?.` 短路，行为与现状逐字节一致（AC-41/AC-R3）。

### 1.2 关键架构决策总表

| # | 决策 | 依据 |
|---|---|---|
| D1 | 剧本条件树 JSON 叶子**必含 `id` + `description`**（与 SuccessCondition 契约逐字段一致） | `LeafCondition.fromJson` 对 id/description 为非空断言（`success_condition.dart:139-141` `json['id'] as String`），缺字段即 type-cast 异常；"复用结构、不复用语义"的最小摩擦实现 = JSON 原样兼容，LessonRuntime 直接调 `SuccessCondition.fromJson`，零适配层。需求文档附录 A 草案中叶子省略 id/description，本方案将其定为**必填契约**（schema 同步 required），示例剧本与 prompt few-shot 全部按此格式 |

| # | 规则 | 对应 AC |
|---|---|---|
| 1 | 必填字段 lessonId/name/version/description/entry/nodes 存在且类型正确；nodes 非空数组；节点必填 id/title | AC-1 |
| 2 | 节点 id 全局唯一（重复 → FormatException） | AC-1 |
| 3 | entry 指向存在节点 | AC-2 |
| 4 | 终点二元绑定：`scenario == null ⇔ advance == null`；终点节点 unlock 必须为 null | AC-11（语义基础） |
| 5 | scenario 非空时 `scenarioPlayable(sim, scenarioId)` 为 true（**存在 + 可完成**双检：objectives/successCriteria 非空且全部叶子 type ∈ 该 sim 已实现求值集，D10） | AC-3 |
| 6 | advance.type ∈ {next, onCompleted, routes}（未知 → FormatException）；next → 非数组末位（无后继 → FormatException）；onCompleted → to 非空且指向存在节点；routes → 非空数组、每项 to 指向存在节点、**末项 when==null 且仅末项可为 null** | AC-4, AC-39 |
| 7 | unlock 与 routes[].when 走 `SuccessCondition.fromJson`（自带：组合键互斥/空数组/嵌套 ≤ maxParseDepth=4 fail loud） | AC-32 |
| 8 | 条件树叶子引用校验：walk 全部条件树 `collectLeaves()`，`nodeCompleted`/`predictionScore` 叶子 params.nodeId、`scenarioSuccess` 叶子 params.nodeId（若提供）必须指向存在节点（D6） | AC-2 同族（防悬空） |
| 9 | 图可达性：从 entry 沿 advance.to / routes[].to / next 后继 BFS，所有节点可达；不可达 → FormatException | AC-5 |

> 解析产物为 `const` 构造的不可变对象树（@immutable）——满足需求 F1"解析产物为不可变对象"。

## 4. 剧本级条件叶子语义表（F8）

条件树结构 100% 复用 `SuccessCondition`（`fromJson` + `evaluate(leafEvaluator)` 注入，`success_condition.dart:37,105-106`），仅叶子语义剧本私有：

| 叶子 type | params 契约 | 求值逻辑 | fail-safe |
|---|---|---|---|
| `nodeCompleted` | `{nodeId: String}` | `_completed.contains(nodeId)` | nodeId 缺失 → false |
| `predictionScore` | `{nodeId: String, metric: 'count'\|'ratio', operator: 'gte'\|'lte'\|'gt'\|'lt'\|'eq', threshold: num}` | 取 `_predictions[nodeId]`；null 或 `verified == 0` → false；`metric='ratio'` → `correct / verified`，`'count'` → `correct`；与 threshold 按 operator 比较 | 无记录 / 未作答 / 未知 metric / 未知 operator / threshold 非数值 → 一律 false |
| `scenarioSuccess` | `{nodeId: String?}`（缺省 = 当前节点） | nodeId 提供 → `_scenarioSuccess.contains(nodeId)`；缺省 → `_scenarioSuccess.contains(current)` | — |
| （未知 type） | — | 一律 false，**不抛异常** | AC-31 |

- 嵌套深度 ≤ `SuccessCondition.maxParseDepth = 4`（`success_condition.dart:34`），超出在 fromJson 抛 FormatException（AC-32）——上限值**直接引用常量**而非复制字面量。
- 组合算子 all/any/not 语义由 SuccessCondition 通用实现（all 短路 false / any 短路 true，`success_condition.dart:104-106`）——AC-27。
- 叶子必含 `id` + `description`（D1，`LeafCondition.fromJson` 非空断言 `success_condition.dart:139-141`）。

## 7. AI 生成链路设计（F13/F14/F15）

### 7.1 `schemas/lesson.schema.json` 结构树（F13）

```
lesson.schema.json (Draft 2020-12 · 参照 color_vision_scenario.schema.json 风格)
├── required: [lessonId, name, version, description, entry, nodes]
├── properties
│   ├── lessonId / name / version / description / entry : string
│   └── nodes : array(minItems 1) → $ref definitions.lessonNode
└── definitions
    ├── lessonNode        : required [id, title]
    │   ├── id / title : string
    │   ├── scenario   : oneOf [ null, $ref scenarioRef ]
    │   ├── unlock     : oneOf [ null, $ref lessonCondition ]
    │   └── advance    : oneOf [ null, $ref advance ]
    │       └── additionalProperties: false
    ├── scenarioRef       : required [sim, scenarioId]
    │   ├── sim          : enum [ 'circuit', 'color_vision' ]   ← 试点封闭（D8）
    │   └── scenarioId   : string
    ├── advance           : required [type]
    │   ├── type         : enum [ 'next', 'onCompleted', 'routes' ]
    │   ├── to / routes  : 条件必填（if/then：onCompleted→to、routes→routes）
    │   └── allOf [if type==onCompleted then required to; if type==routes then required routes]
    ├── route             : required [to] · properties { to: string, when: oneOf[null, lessonCondition] }
    ├── lessonCondition   : oneOf [ conditionLeaf, criterionAll, criterionAny, criterionNot ]
    │                       （组合三件结构与 _shared/combinable_criteria.md / 8 份 sim schema
    │                         的 criterion oneOf 模式完全同构——可复制任一为模板）
    └── conditionLeaf     : required [id, type, description]
        ├── type         : enum [ 'nodeCompleted', 'predictionScore', 'scenarioSuccess' ]
        └── params       : object
```

**schema 表达力边界**（需求 F13"如 schema 可表达"）：① routes 兜底路由"仅末项 when=null"的**位置**约束、② 嵌套深度 ≤4、③ entry/to/nodeId 跨字段引用存在性——三者超出 JSON Schema 合理表达范围，由 **Dart 解析器 fail loud**（§2.1 规则 6/7/8/9）+ **prompt 规则**双层兜底；schema 覆盖其余全部结构/枚举/必填约束（AC-46~48 用正反例验证 schema 覆盖面）。
