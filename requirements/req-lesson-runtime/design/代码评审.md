#### Blocker-1 · rgb 完成信号只在挑战模式触发，自由探索模式永不外发（偏离 D4 与 T-P1-14 任务卡）

**证据**

- rgb_bulbs_screen.dart:258 —— 全文件唯一的 widget.onScenarioSuccess?.call()，位于 _notifyChallengeObjective()（:251-260）内。
- 该方法唯一调用方 rgb_bulbs_screen.dart:211，受 acc >= _accuracyThreshold && _challengeActive 门控（:207）。
- _calcAccuracy() 仅在挑战模式渲染路径被调用：:494（挑战画布，门控 :482 _mode == LabMode.challenge）与 :747（_challengeProgressRow，由 :658 挑战分支渲染）。
- 任务卡 tasks/features.json:270-271 明确要求新增 _maybeNotifyObjectiveMet()，并在 _onDragUpdate / _miniSliderVertical 的 Slider onChanged / _startChallenge 归零后**三处**调用。实际代码这三处（:275-285 / :812 / :177-197）**均无调用**。方案 §2.8 rgb 行与 D4 同口径。

**问题**：学生在自由探索模式把 R/G/B 调到满足 successCriteria 时，剧本层收不到完成事件，节点永不流转。这与 T-P1-06 在 circuit 侧刚修掉的缺陷（判定门控致完成信号死路，process.txt:19 发现①）是**同一类缺陷在 cv 侧未修**。

**影响面**：全部 color_vision 剧本节点（cv-additive-linear ×3 / cv-challenge-path ×3 / cross-sim-explore 的 n2）→ AC-8 / AC-26 / AC-45 / AC-58。

**建议修法**：按任务卡原文实现 _maybeNotifyObjectiveMet()（首条件 widget.onScenarioSuccess != null，保证不传钩子零新路径 · AC-R3），挂 _onDragUpdate（:279 setState 之后）、_miniSliderVertical 的 onChanged、_startChallenge 归零后三处；与 _notifyChallengeObjective 共用 _objectivesMetNotified 防重复。必须配一条 widget 测试（见 §5 T1）。
