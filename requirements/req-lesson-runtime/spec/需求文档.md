## 1. 背景与目标

### 1.1 业务背景

KratosLab 的场景体系当前为"单场景孤岛"架构——ScenarioManager 按 id 加载单个独立实验，场景间无依赖、无顺序、无分支（S1 §1.1/§2）。这导致无法表达"老师编排完整课时"（40 分钟 = 3-5 个实验场景按序/按条件流转）。

评估报告（S1）已完成方案对比并推荐**方案 B——新增 lesson-plan 编排层**：剧本是独立的顶层引用式资产，以纯增量方式复用 `ScenarioManagerBase.loadScenario`、`SuccessCondition` 条件树、AI 三件套三大既有资产，零触碰 46 个存量场景与 8 份 manifest。用户已 verdict=go（S3）。

### 1.2 实现目标

在不破坏现有场景体系的前提下，为 KratosLab 增加**课时级多场景编排能力**：

| 目标 | 说明 |
|------|------|
| **学生可按编排走完课时** | 加载剧本 → 按节点顺序/条件自动流转 → 完成课时 |
| **教师可手写/AI 生成剧本** | 标准化 JSON 格式 + schema 校验 + prompt 引导 AI 生成 |
| **新旧模式共存** | 无剧本时走传统自由选场景模式；有剧本时走编排模式；互不干扰 |

### 1.3 范围边界（已锁定，S3/S4）

| 包含（P1-P3） | 排除 |
|---------------|------|
| P1 线性编排地基（~5 人天） | P4 B 类 4 sim（sound/radio_waves/wave_interference/forces）判定接线 |
| P2 条件编排（~4 人天） | P5 进度持久化（跨 session） |
| P3 AI 生成链路（~3 人天） | 作者侧可视化编排 UI（C4 禁区） |
| | 跨场景实验数据传递（G5，表达力边界） |

## 3. 详细功能描述

### 3.1 F1 · LessonPlan 数据模型

**目标**：将 `assets/lessons/<lessonId>.json` 解析为强类型数据模型，含完整性校验。

**数据结构契约**（基于 S1 §5.1 PoC 设计）：

```
LessonPlan
├── lessonId: String（唯一标识）
├── name: String（课时名称）
├── version: String（格式版本）
├── description: String（简述）
├── entry: String（入口节点 id）
└── nodes: List<LessonNode>
    ├── id: String（节点唯一标识）
    ├── title: String（节点标题）
    ├── scenario: {sim: String, scenarioId: String}?（null = 终点节点）
    ├── unlock: SuccessCondition?（null = 无门禁）
    └── advance: Advance?（null = 课时终点）
        ├── type: "next" | "onCompleted" | "routes"
        ├── to: String?（onCompleted 时的目标节点）
        └── routes: List<Route>?（routes 时的条件路由表）
            ├── when: SuccessCondition?（null = 兜底路由）
            └── to: String
```

**解析行为**：
- **fail loud**（沿用 SuccessCondition 模式）：格式错误 / entry 指向不存在节点 / 节点引用场景不存在 / 路由目标悬空 / 图有不可达节点 → 抛 `FormatException`
- **课时级降级**：FormatException 导致该课时跳过（从 manifest 移除展示），不影响其他课时和传统场景模式
- 解析产物为不可变对象

**验收标准**：

| # | 验收条件 | 来源 |
|---|---------|------|
| AC-1 | 合法剧本 JSON（含线性/条件/解锁三种编排模式）可被正确解析为 LessonPlan 模型，所有字段可访问 | S1 §5.1 |
| AC-2 | entry 指向不存在节点 → FormatException，错误信息含 lessonId + 原因 | S1 §4.2 R2 |
| AC-3 | 节点 scenario.scenarioId 引用不存在的场景 → FormatException（加载期校验）| S1 §4.2 R2 |
| AC-4 | routes 路由目标 to 指向不存在节点 → FormatException | S1 §5.2 |
| AC-5 | 图中存在不可达节点（从 entry 出发无法到达）→ FormatException | S1 §5.1 |
| AC-6 | FormatException 发生时该课时被跳过，不 crash、不影响其他课时/场景 | S1 §4.2 R2, S4 |

### 3.2 F2 · LessonRuntime 状态机

**目标**：驱动剧本运行——从加载到节点流转到课时完成的全流程状态管理。

**四步契约**（S1 §5.2）：

| 步骤 | 方法 | 职责 |
|------|------|------|
| 1. 剧本加载 | `load(lessonId)` | 读取 JSON → 解析 LessonPlan → 校验引用存在性 → 进入 entry 节点 |
| 2. 节点进入 | `enterNode(nodeId)` | 复用 sim screen 既有场景加载路径加载目标场景（circuit：`ScenarioManagerBase.loadScenario(scenarioId)`；color_vision：`findById` + `setCurrentScenario` 既有模式——v1.1 同步技术方案 D3 口径）→ 渲染 sim screen（携带事件钩子）；终点节点触发课时完成 |
| 3. 自动流转 | `advanceFrom(nodeId)` | 根据 advance.type（next/onCompleted/routes）判定下一节点并 enterNode |
| 4. 完成判定 | `onScenarioSuccess()` | 场景 successCriteria 全满足 → 标记节点 completed → 触发 advanceFrom |

**状态暴露**：
- `current`：当前节点 id
- `completed`：已完成节点集合
- `progress`：进度（completedCount / totalRequiredNodes）
- `isUnlocked(nodeId)`：指定节点是否已解锁

**验收标准**：

| # | 验收条件 | 来源 |
|---|---------|------|
| AC-7 | load 成功后 current = entry 节点，对应场景已通过 ScenarioManager.loadScenario 加载 | S1 §5.2, S4(C5) |
| AC-8 | 线性课时（3 节点 A→B→C）：A 场景完成 → 自动进入 B → B 完成 → 自动进入 C → C 完成 → 课时完成 | S1 §5.1 |
| AC-9 | advance.type="next" 时按 nodes 数组顺序取下一节点 | S1 §5.2 |
| AC-10 | advance.type="onCompleted" 时跳转到 advance.to 指定节点 | S1 §5.2 |
| AC-11 | 终点节点（scenario=null）进入时触发课时完成（非 crash） | S1 §5.2 |
| AC-12 | LessonRuntime 调用场景加载时使用的是既有 ScenarioManagerBase.loadScenario(id)，零改动（C5） | S4(C5) |
| AC-13 | 运行时全程 progress 可查询且值正确（completed/total） | S1 §5.2 |

### 3.3 F3 · Lessons Manifest

**目标**：`assets/lessons/manifest.json` 注册所有可用课时，供首页/加载器消费。

**结构**：

```json
{
  "version": "1.0",
  "lessons": [
    { "id": "circuit-ohm-law-40min", "file": "circuit-ohm-law-40min.json", "name": "欧姆定律课时", "sim": "circuit" }
  ]
}
```

> **`sim` 字段语义**（v1.1 补充，对齐技术方案 D9）：**入口归属 sim**，单值——① 首页入口卡片分组挂载依据；② 混合 sim 剧本（同课时节点跨多个 sim）取 entry 节点的 `scenario.sim`。运行态各节点宿主由剧本内各节点 `scenario.sim` 决定（技术方案 `LessonSimHosts.dispatch()`），与本字段解耦。

### 3.8 F8 · 剧本级条件树

**目标**：复用 SuccessCondition 的 all/any/not JSON 契约结构，注入剧本级叶子求值器。

**剧本级叶子封闭枚举**（S1 §5.1）：

| 叶子 type | 语义 | 依赖 |
|-----------|------|------|
| `nodeCompleted` | 指定节点已完成 | LessonRuntime 自身进度状态（无外部依赖） |
| `predictionScore` | 指定节点预测题正确率/数达阈值 | req-predictive-inquiry: PredictionPanel.onResultChanged |
| `scenarioSuccess` | 指定场景 successCriteria 曾全满足 | req-criteria-composable: A 类 sim 判定链 |

**求值模式**：复用 `SuccessCondition.evaluate(leafEvaluator)` 注入模式——"复用结构、不复用语义"（S1 §1.2）。

**验收标准**：

| # | 验收条件 | 来源 |
|---|---------|------|
| AC-27 | 剧本条件树使用与 SuccessCondition 相同的 JSON 契约格式（all/any/not 组合） | S1 §1.2, S4 |
| AC-28 | `nodeCompleted` 叶子：指定节点已完成时求值 true，否则 false | S1 §5.2 |
| AC-29 | `predictionScore` 叶子：metric=ratio + operator=gte + threshold=0.8 时，正确率≥80% 求值 true | S1 §5.2 |
| AC-30 | `scenarioSuccess` 叶子：场景 successCriteria 全满足后求值 true | S1 §5.2 |
| AC-31 | 未知叶子 type 一律求值 false（fail-safe，不抛异常） | S1 §5.2 |
| AC-32 | 条件树嵌套深度上限复用 SuccessCondition 的 maxParseDepth=4，超出 → FormatException | S1 §4.2 R6, S4 |
| AC-33 | 未作答（verified=0）时 predictionScore 求值 false（fail-safe） | S1 §5.2 |

### 3.9 F9 · unlock 门禁

**目标**：节点可配置 unlock 条件，未解锁节点不可手动进入。

**行为**：
- unlock=null → 无门禁，始终可进入
- unlock=条件树 → 条件满足后解锁
- 未解锁节点在进度 UI 中标注"锁定"态，点击不响应

**验收标准**：

| # | 验收条件 | 来源 |
|---|---------|------|
| AC-34 | 带 unlock 的节点：前置条件未满足时 isUnlocked=false，UI 展示锁定态 | S1 §5.1/§5.2 |
| AC-35 | 前置条件满足后 isUnlocked=true，可正常进入 | S1 §5.2 |
| AC-36 | unlock=null 的节点始终 isUnlocked=true | S1 §5.1 |

### 3.10 F10 · routes 条件路由

**目标**：advance.type="routes" 时，按条件路由表顺序求值，进入首个满足条件的目标节点。

**行为**：
- routes 数组按序遍历，首个 when 求值 true 的路由生效
- 末项 route.when=null 为兜底路由（必须存在）
- 所有 route.to 指向的节点必须在 nodes 中存在（解析期校验）

**验收标准**：

| # | 验收条件 | 来源 |
|---|---------|------|
| AC-37 | 条件路由按 routes 数组顺序求值，首个 when=true 的 to 生效 | S1 §5.2 |
| AC-38 | 所有 when 为 false 时进入兜底路由（末项 when=null） | S1 §5.2 |
| AC-39 | routes 无兜底路由（所有项均有 when）→ 解析期 FormatException | S1 §5.1 |

- `--lesson` 参数启动剧本生成模式
- 生成后自动用 lesson.schema.json 校验
- 校验通过后写入 `assets/lessons/<id>.json`
- 自动更新 `assets/lessons/manifest.json`（追加 entry）
- 自动从 8 份 sim manifest 提取场景 id 清单注入 prompt 上下文

**验收标准**：

| # | 验收条件 | 来源 |
|---|---------|------|
| AC-52 | generate.py --lesson 模式可执行不报错 | S1 §4.3 |
